# 历史成本与效果评测：2026-10-06 BGL 小样本

本页只记录早期 BGL 试验，不能与当前 Kaggle 矩阵合并或当作当前模型结果。当前口径、模型、评分锚点和运行目录见 [评测说明](../evals/README.md)；当前运行的真实请求与账单保存在 `evals/results/20261006-kaggle-matrix/`。

## 数据和频率

公开集为 [LogHub BGL 2k](https://github.com/logpai/loghub/blob/dd61d0952749ee7963bde24220d1be5ede023033/BGL/BGL_2k.log_structured.csv) 的两个固定400行窗口：第一窗口94行有公开异常标签，第二窗口无异常标签，但含严重级别日志，可检验“级别高就一定失败”的误判。标签只给 judge，业务模型只读取字段白名单，不给 BGL 杜撰 HTTP 请求状态。许可/引用见 [LogHub notice](../evals/LOGHUB-LICENSE.txt)。

第二类是仓库确定性生成的两个合成请求样例：100请求 / 103尝试，95成功、3最终失败、2取消、6失败尝试、3重试恢复；后一例有长描述及日志内指令干扰。它们不是生产数据或第三方基准，随代码提供生成器，信度与公开日志分开讨论。

共4样例，每条件手动运行一次。裁剪条件采用字段96、来源1,200、总输入2,000 tokens；完整 JSON 不裁剪。弱摘要用 `gpt-5.6-luna / low`，强分析配置 `gpt-5.6-sol / medium`，实际计费模型均为 `gpt-6.1-sol`。最终提示词和输出预算相同；两段流程的强模型只接收按相同巡检需求生成的摘要。没有固定周期，没有独立人工评分，也没有随机重复生成来估计方差。

## 实际业务成本

下表费用是**四个样例合计**，来自远端 AxonHub `usage_logs.total_cost`，不是定价估算。prompt / completion / total 也是上游计量；采集正文列使用本地 tokenizer，只包括经过来源包装/裁剪的正文，不包括模型提示词或上游附加前缀。

## 信息保留与效果状态

格式和限额共同决定留下多少数据。以下是保留完整字段集合的记录数；仍可能存在字段描述被截短，所以也不能把它视为语义完整率。

| 样例 | 原始记录数 | 裁剪 JSON | 裁剪 ISON | 裁剪 ZON |
| --- | ---: | ---: | ---: | ---: |
| BGL窗口1 | 400 | 33 | 39 | 45 |
| BGL窗口2 | 400 | 25 | 5 | 32 |
| 重试 / 取消样例 | 103次尝试 | 34 | 7 | 50 |
| 长错误样例 | 103次尝试 | 33 | 7 | 50 |

同格式的两段摘要路线使用相同裁剪输入；摘要后事实是否进一步损失，需要 judge/人工检查。ISON 在部分同构表格裁剪中只留下很少近期记录：例如窗口2是4条严重日志 + 1条近期日志。773.25 tokens 的小输入不能宣传成等价于完整数据的“更高压缩率”。ZON 此轮关闭了1.2.3字典压缩中丢失尾随空格的有损路径，保留表格/差分编码与严格等价校验。

judge 计划比较每个条件与完整 JSON，交换A/B位置各一次，按异常证据、事实一致性、统计口径、可追溯性、不确定性和行动边界各1–5分。40次请求均未取得有效评分：6次HTTP403、33次HTTP500、1次读取超时。失败来自本轮选用的上游渠道：一个渠道报告 `INSUFFICIENT_BALANCE`，另一路报告每分钟10请求（含失败）限制与429，后续路由出现500/超时。客户端请求固定 `gpt-6-luna` / `max`；独立探针 request `202241` 已验证模型与推理档，探针账单 `$0.0000202` 单独记录，不混入上表。

**质量分、胜率、位置冲突率均为未验证。judge费用无法完整关联，记为 missing，不记成$0。** 整次评测状态为 partial；业务费是已核实的成本，不是含所有失败judge费用的总账单。

上游额度恢复后设置 `EVAL_BASE_URL` / `EVAL_API_KEY`，仅重跑 judge，复用已付费生成的报告：

```bash
uv run python -m evals.run_eval --judge-only evals/results/20261006-pilot --judge-interval 12
# 对命令返回的新目录执行
uv run python -m evals.costs evals/results/实际新目录
uv run python -m evals.report evals/results/实际新目录
```

新目录保留原业务调用响应ID，不重新生成或计费；原失败批次留作诊断。渠道恢复后，后续 judge 串行并限速，仍需该渠道有有效余额，且共享账户的其他任务可能占用限额。完整运行材料保存在本地 ignored `evals/results/20261006-pilot/`；机器汇总与账单证据已作为可审阅产物保留。最低硬件仍等待单独租机验证。

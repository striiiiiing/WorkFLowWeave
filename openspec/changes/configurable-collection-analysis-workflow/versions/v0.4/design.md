# v0.4：浏览器控制台与画布

## 1. 范围

依据 proposal §4 的漂亮前端与画布式设计，提供可从服务首页直接打开的中文操作界面，完成资源配置、流程编排、运行结果、评估与会话闭环。以前三个版本的 API 为唯一业务来源。

## 3. 页面与交互

### 3.1 控制台结构

侧栏提供工作流、资源、运行记录、评估、对话入口；顶部显示连接状态、当前工作流和保存/运行按钮。主区默认画布，右侧检查器编辑选中节点的业务设置。采用清晰排版、低饱和深色侧栏与浅色工作区、可区分的来源/分析/汇聚/通知节点颜色；状态同时有文字与图标。窄屏折叠侧栏和检查器，表单支持键盘操作与可见焦点。

### 3.2 可编辑画布

节点来自 Workflow 的 sources/analyses/fan_in/channels。每个节点可以移动、选择、配置和删除；画布支持新增分析分支、选用已有资源、开关汇聚、调整来源/分支/通知顺序、连接/断开分析的来源。边跟随节点移动更新；默认分析连到全部来源，子集通过输入连接表达。工作流仍为既有固定阶段模型，不声称支持任意环路 DAG。

布局保存为与业务配置分离的 UI 元数据（以 workflow ID 索引），不让位置数据绕过 WorkflowDefinition 严格 schema。重新打开恢复布局，支持导入/导出 JSON；导入先检查结构，再通过真实 API 验证。高级参数可以使用 JSON 编辑器，但常用来源选择、提示词、模型、分支模式、汇聚顺序、Channel、定时、备份设置有表单。

### 3.3 运行与资源

运行按钮先保存当前有效定义，再触发并跟踪真实 session。显示阶段进度、来源状态、每个分支、汇聚、投递与恢复范围；可取消、恢复、查看备份。资源页面提供插件 schema、来源/Setter/AI/Channel/健康/命令的创建编辑删除，字段错误就地显示，失败时保留输入。

### 3.4 评估与讨论

评估页选择基准 session 和候选、配置规则及可选评分模型，展示耗时/usage/评分/错误并列报告。对话页显式选择关联运行与 AI，保留会话列表、历史和系统模板；新通知不切换当前对话。前端只使用文本节点渲染模型/日志内容，避免把不可信结果当 HTML。

## 4. 资源与部署

静态资源随 Python 包提供，由 FastAPI 同源服务；不要求额外数据库、Node 运行时或前端开发服务器。浏览器脚本按 API、状态、画布、表单/页面划分，CSS/HTML 作为包数据包含在构建产物中。所有资源本地可用，不依赖远程 CDN 或字体。

## 5. 验收

先做 API 和静态资源集成测试，再使用真实浏览器验证打开、资源保存、创建流程、拖拽、连线、刷新保持布局、触发与结果查询、错误显示、评估和会话。测试应检查实际 DOM 与请求效果，不能只检查文件含某段文字。保存宽屏/窄屏截图作为视觉验收证据。最后运行整个项目测试、构建和 CLI 快速开始，记录仍未实际执行的外部服务/24 小时验证边界。

# 交互模块提案（v0.1）

关联：[根 proposal](../../proposal.md) §2.1「交互模块」、§3 验收标准 9，[根设计](../../design.md) §4.2，[模块设计](./design.md)。

## 1. 背景与目标

用户需要通过 JSON 配置来源、AI、Channel 和 Workflow，触发执行并查看历史及备份。交互模块提供统一 API 和薄 CLI，使配置校验、运行行为与后续 Channel 内部调用保持一致。

应用装配同时负责异步资源和后台任务的生命周期，确保启动失败、关闭和运行取消都有确定行为。

## 2. 本期范围

- 使用 FastAPI 提供 `/api` 下的配置资源增删改查、插件能力发现、运行触发和查询接口。
- 覆盖 Source、Setter、AI、Channel 和 Workflow 的完整语义验证，错误包含字段路径与可修正原因。
- 提供 session 列表、阶段状态、投递状态、备份读取、恢复和取消接口。
- 采用统一错误格式区分校验、缺失、引用或状态冲突、容量不足及存档不可用。
- 使用 Typer 提供服务启动、离线样例生成和必要的 HTTP 调用命令。
- 使用 uvicorn 单进程运行；通过 lifespan 装配配置、插件、业务服务、模型客户端及定时调度。
- 关闭时停止准入、回收运行与调度任务，再关闭插件和 HTTP 客户端，记录后台异常。

## 3. 明确边界

CLI 业务操作使用 HTTP，不直接执行 Workflow 或绕过业务 schema 读写资源；`serve` 和 `init` 仅承担启动及样例生成。

首版不实现浏览器前端、复杂 CLI、安全服务、外部触发 Webhook 或双向会话。默认回环地址和单进程部署，不声称多个 worker 共享调度锁。

API 返回触发已接受，不等于 Workflow 已成功；业务结果通过 session 查询。备份不可用时返回明确原因，不读取当前资源或原来源来伪造历史。

恢复只能使用原 session 快照和已有材料，不能覆盖资源或切换最新模板。最终输出已冻结的 session 只允许补发失败通知；重新分析使用新的触发操作。

## 4. 验收标准

| 编号 | 可验证行为 |
| --- | --- |
| API-01 | 所有资源可完成有效的增删改查，重复 ID 与被引用资源删除有明确冲突。 |
| API-02 | 无效 Collector schema、Setter、AI、Channel 能力和 Workflow 引用返回带路径的 422，未产生半配置资源。 |
| API-03 | 触发及时返回 202 和 session 地址；后续业务成功、部分成功或失败可独立查询。 |
| API-04 | session 及存档接口只读取已有内容，关闭、过期、损坏和缺失可区分，禁止任意路径读取。 |
| API-05 | 恢复和取消调用统一业务入口；状态冲突、恢复条件不足和容量不足映射正确状态码。 |
| API-06 | CLI 业务命令实际使用 HTTP，正确输出结果和错误退出码，不重复业务实现。 |
| API-07 | init 样例完全离线可运行，不覆盖已有用户文件。 |
| API-08 | 正常及部分失败的 lifespan 均能释放资源，关闭后没有遗留后台任务或新增通知。 |
| API-09 | 真实本地 API 配合离线 Mock 通过端到端及十分钟稳定性验证，资源报告据实记录。 |

## 5. 依赖、产物与实施边界

依赖其它六模块的根接口契约及公共错误模型。路由和 CLI 可先使用替身验证协议，最终验收必须通过真实服务装配完成。

预期代码为 `logagent/api.py`、`logagent/cli.py`、`logagent/app.py`，共享 `logagent/models.py`；测试覆盖 API、CLI 和应用生命周期。此模块在独立目录维护 proposal、design 及后续任务文档，完成实现与测试后再记录验收结论。

# Task 1: 定义文件渠道声明与单条 JSON Lines 格式

描述：声明 mock 的 notification 能力及 path 选项，固定从通知到单条 UTF-8 JSON Lines 记录的转换；预计 30 分钟。

输入：Mock 渠道规范、Notification/ChannelConfig 契约、配置阶段确定的有效绝对路径。

输出：mock 类型声明、仅含 path 的 options_schema、无 I/O 的通知序列化函数。

依赖：channel 模块的渠道公共模型与实例协议；config 模块的相对 data_dir 解析并固定快照路径能力。

验收标准：
- path 为非空路径且未知 options 被拒绝，不增加延迟、错误开关等生产配置字段。
- 每条记录包含 session_id、output_id、title、text、metadata 并以一个换行结束，UTF-8 解码及 JSON 解析可还原原始内容。
- 正文中的换行、引号及 Unicode 正确转义，不造成一条通知占用多个 JSON Lines 记录。
- 路径只来自固定配置，正文和 metadata 不影响写入目标；校验与序列化不创建文件。

# Task 2: 实现完整追加、路径互斥与取消边界

描述：实现短生命周期文件适配器，按规范化路径共享进程内短写入互斥区，并覆盖阻塞写入在取消后的真实生命周期；预计 75 分钟。

输入：mock 声明、完整序列化记录、规范化绝对路径及可控制文件写入的测试替身。

输出：mock 实例工厂及 start/send/stop、可回收路径锁管理、部分写入与取消的不确定性诊断。

依赖：Task 1；channel 模块的实例协议及平台错误到回执所需的接收事实约定。

验收标准：
- start 创建缺失父目录，send 使用 append 写入完整记录并刷新后成功，stop 释放句柄；既有文件内容保持不变。
- 同一规范化路径的并发实例共用互斥区，序列化位于互斥区外，锁在实际写入结束后释放，空闲锁引用可回收。
- 若采用线程 I/O，协程取消不提前释放线程持有的互斥区或关闭仍在写入的句柄。
- 部分写入及写入开始后的超时/取消标记不确定性，不返回成功、不再次追加；尚未写入的权限或目录错误明确报告。
- 成功语义是完整记录已写入并刷新；实现不额外承诺 fsync 级别断电持久性，不引入发送缓存或跨 session 顺序承诺。

# Task 3: 验收并发完整性与失败回执

描述：以临时文件和故障注入验证跨实例记录边界、内容保留及网关回执，提供本地通知示例；预计 60 分钟。

输入：mock 适配器、网关发送与取消实现、临时目录及可控短写入/延迟写入替身。

输出：文件渠道验收用例、本地通知配置示例和执行记录。

依赖：Task 2；channel 模块的单条发送与回执协调器、有界取消与关闭实现。

验收标准：
- 多 session、多实例对同一路径并发追加后，所有完整行均可逐条解析，记录不交错、不丢失，原有文件前缀保持原样。
- 同一路径的不同规范化表达共用写入互斥区；不同路径可独立推进，不被一个全局写锁串行阻塞。
- 多行和 Unicode 正文往返一致，回执标识与实际记录匹配，成功调用各追加一次。
- 目录/权限错误、部分写入、刷新失败、超时及取消均可通过测试替身稳定复现，失败不被转换成成功或自动重试。
- 线程写入在调用方取消后仍完成收尾的场景不会引发后续记录交错或句柄竞态，相关回执保留接收不确定性。

# Mock 文件渠道设计

[Channel 网关](../design.md) · [ChannelConfig 契约](../../../contracts/data-models.md#24-channel-配置)

注册名为 mock，能力为 notification。此渠道实现提案要求的“把通知追加到文件尾部”，用于本地查看和离线验收。

## options

| 字段 | 类型及约束 | 解释 |
| --- | --- | --- |
| path | 非空路径，必填 | 通知输出文件；相对 data_dir 解析，并在快照中固定有效绝对位置。 |

固定使用 UTF-8 JSON Lines，每次追加一个包含 session_id、output_id、title、text、metadata 的 JSON 对象和换行。JSON 转义保持正文中的换行与内容，文件不存储凭据。

## 一次追加

start 准备路径，父目录不存在时创建；权限错误直接报告。send 先在内存序列化整条记录，再以 append 模式写入并刷新，成功后返回；stop 释放句柄。失败不能返回成功，也不截断或覆盖已有文件。

同一进程内，相同规范化路径共用一个短写入互斥区，防止不同 session/实例的记录字节交错；这只保护文件完整性，不存储待发送消息或承诺跨 session 顺序。序列化在互斥区外完成，锁在 finally 释放，空闲锁引用可回收。

阻塞文件 I/O 可以放入线程；取消协程不代表线程已停止。线程必须持有互斥区直到写入实际结束，已开始写入后超时/取消或部分写入标记不确定性；不再次追加。成功意味着本次完整记录已写入并刷新，首版不承诺 fsync 级别断电持久性。

Mock 的生产配置只保留 path。故障/延迟模拟通过测试替身或不可写路径完成，不增加一组用户日常配置字段。

## 验证要点

多行正文可逐行解析回原内容；多 session 同路径追加记录不交错；目录/权限错误可诊断；部分写入和取消不静默重试；原有文件内容保留。

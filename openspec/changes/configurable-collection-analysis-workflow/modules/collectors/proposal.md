# 数据采集模块提案（v0.1）

本模块依据 [根 proposal.md](../../proposal.md) §2.1「数据采集模块」、§3「验收标准」及 [根 design.md](../../design.md) §1.3、§4.2。详细契约与测试场景见 [design.md](./design.md)。

## 1. 要解决的问题

Workflow 需要配置多个可复用的数据源，并获得可解释的文本、计数和执行状态。来源访问方式与可配置字段由各 Collector 决定；缺少统一的发现、校验和结果结构，会让 Workflow 混入每种来源的实现细节，也无法区分采集故障和正常空结果。

历史 Workflow 结果还需要再次成为输入，为后续运行提供已有信息。这一读取必须依据存档完成，不能为了获得历史内容重新执行原始采集或模型分析。

## 2. 本模块交付范围

- 提供轻量 `BaseCollector` 与 `CollectorManager`，通过协程执行单来源采集，公共结果采用 `CollectionResult`。
- 在启动时发现 `plugins/Collectors/*.py`；一个插件可以注册多个来源类型。按文件隔离导入、配置、声明和重复名称错误，失败文件不得留下部分注册。
- 暴露来源专属 options schema、Setter schema、字段、分组及计数能力；只接收 Collector 已声明的设置，配合配置模块复用 Setter 模板。
- 提供内置 `mock`、`history`、`logs` 来源。历史支持指定 Workflow、最近次数、时间范围和明确算法的 token 预算；日志使用有界尾部读取。
- 返回来源内容、处理前后计数和状态，明确区分 `success/empty/filtered_empty/missing/failed/timeout`。
- 为来源执行提供超时、取消和错误诊断，使单个来源失败不会阻塞其他独立来源的执行或插件发现。

## 3. 协作边界

| 协作对象 | 本模块输入或输出 |
| --- | --- |
| 配置与资源管理 | 接收已展开、确定的 `SourceConfig`；验证 options 和 Setter，不保存模板或改变资源引用 |
| Workflow | 接收单来源调用，返回采集结果；来源顺序、共享输入拼接及停止/跳过策略由 Workflow 处理 |
| 运行记录与存档 | 读取已有 session 和阶段内容；尊重缺失、关闭、过期和损坏的可用性结果 |
| 交互模块 | 提供可查询的 schema 和诊断；API 负责响应格式及错误状态映射 |

模块参考 QwenPaw 解读中的“类型注册与运行实例分离”，保持 Collector 父类轻量。首版不实现健康监测循环、YAML Toolset、图片来源、插件热更新、复杂采集运行时或任意命令执行能力。

## 4. 验收标准

1. 空插件目录下可使用三个内置来源；坏插件或同名注册不影响其他有效来源，一个失败文件不产生部分注册。
2. 已声明的字段、过滤、排序和分组产生稳定结果及准确计数；未知配置、未知 Setter 和不兼容模板在执行前报出字段错误。
3. 正常无原始记录、处理后无记录、来源缺失和来源失败分别返回对应状态；Workflow 可以据此执行各自策略。
4. 历史按最近 session 次数、时间边界和 token 预算选择内容；预算算法可复算，超限只按配置截取完整记录或报错。
5. 无历史返回正常空结果，缺失备份和损坏备份可区分；读取历史期间原始 Collector、Workflow 和 AI 的调用次数均为零。
6. 大日志只读取配置字节和行范围，正确处理 UTF-8 边界、半行、文件不存在及权限错误。
7. 来源超时、并发和取消的测试使用可控协程及临时文件，单来源故障不使其他来源无法完成，不留下无人跟踪的后台任务。

## 5. 交付与依赖

实现位于 `logagent/collectors/`，共享模型位于 `logagent/models.py`。实施依赖公共模型、配置展开及 Archive 的读取契约；插件、Mock、Setter 和日志可使用替代依赖独立测试。完成详细设计后编写本模块 `tasks.md`，按任务验收与提交。

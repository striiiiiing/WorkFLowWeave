# AI 模块提案（v0.1）

关联：[根 proposal](../../proposal.md) §2.1「简易 Agent 模块」、§3 验收标准 4/8，[根设计](../../design.md) §4.2，[模块设计](./design.md)。

## 1. 背景与目标

Workflow 的多个分析分支需要使用不同的模型、提示词和配置，但执行接口应保持一致。首版提供可复用的单次分析服务，让 fan-out 和可选 fan-in 共用模型适配、系统提示词及工具能力，同时为后续 Agent 留出边界。

输入是调用方明确提供的完整文本，输出是带状态、用量和耗时的 `AnalysisResult`。本模块不决定采集范围、Workflow 并发、备份或通知。

## 2. 本期范围

- 实现 `AIService.validate()` 和异步 `execute()`，统一模型调用和错误结果。
- 提供无需凭据的离线 Mock，以及通过 HTTP 请求兼容聊天模型的提供方。
- 支持独立系统提示词、任务提示词和 `{input}` 填充；无占位符时附加完整输入。
- 接受模型专属 JSON 参数并保护服务控制字段，拒绝 `temperature/top_k`。
- 注册有名称、描述、参数 schema 和异步 callable 的工具，配置只引用已注册工具。
- 实现有界工具调用，保存调用 ID、结果、错误及耗时，允许 Workflow 将事件写入存档。
- 为连接、请求、工具和总执行设置时间边界，支持取消以及应用关闭时的客户端释放。

## 3. 明确边界

首版不实现完整双向 Agent、自动连续对话、YAML Toolset 或无限规划循环。分析服务不隐式重新读取来源，不在内部决定失败分支重试，也不提供任意 shell 执行入口。

凭据以环境变量名保存，运行时解析；秘密不写入配置快照。测试使用 Mock transport 和测试凭据，不要求真实模型费用或宿主账户。

后续 Agent 可复用同一 AI 配置、提供方和工具注册表，并采用独立的多步执行策略。首版保留 session、任务和阶段关联，不建立对话状态机。

## 4. 验收标准

| 编号 | 可验证行为 |
| --- | --- |
| AI-01 | Mock 能离线返回确定的 `AnalysisResult`，正确关联任务并报告耗时。 |
| AI-02 | HTTP 请求使用有效配置，系统和用户角色分开，完整输入未被裁剪或串到其它分支。 |
| AI-03 | 无效提供方、未知工具、被禁参数及受保护字段覆盖在执行前被拒绝。 |
| AI-04 | HTTP 故障、无效响应和超时为明确非成功状态，不伪造文本或用量。 |
| AI-05 | 工具参数按 schema 校验；每次调用 ID、结果及错误可追踪，执行总量有界。 |
| AI-06 | 多个调用可并发推进，取消会阻止后续工具和模型请求，客户端可关闭。 |
| AI-07 | 配置、错误、结果和日志中不出现解析后的凭据。 |
| AI-08 | Workflow 分析和 fan-in 使用同一接口；服务不强制依赖 Workflow 上下文。 |

## 5. 依赖、产物与实施边界

依赖公共模型和配置模块提供 `AIConfig`；生产请求使用异步 HTTP 客户端，工具使用 JSON schema 校验。Workflow 负责注入原配置快照和保存工具事件，交互模块负责客户端生命周期。

预期代码位于 `logagent/ai/`，针对契约的测试位于 `tests/test_ai.py`。本模块按独立 `tasks.md` 实施并验收；当前文档不代表实现或测试已经完成。

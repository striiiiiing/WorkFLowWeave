# 设计：由双向渠道实例持有对话绑定

状态：2026-10-05，用户已确认简单实现并授权实施；本次补充 `/resume` 改绑、内存缓存及加锁顺序后继续实现。

## 1. 依据与替代关系

用户明确要求：“一个渠道实例绑定一个对话”“双向渠道拥有对话，而非对话选择渠道”“接收只给到渠道绑定的对话中”，并要求高优先级指令分流、Web 调试、前端实例绑定，以及复用 Workflow 通知发送。

本设计在该范围内优先于 [旧 ChannelManager 设计](../redesign-agent-channel-manager/design.md) 第 4 节的按好友/群成员创建和绑定对话规则，以及第 7 节当时不修改前端的范围约束。旧设计保留作为历史；[通知插件设计](../add-notification-channel-plugins/design.md) 的插件目录、SDK 优先、Email SMTP、file logging 和 Collector 删除方案继续适用。

源码参考为旁边开源项目 `QwenPaw`：

- `src/qwenpaw/app/channels/manager.py`：`enqueue` 提交到应用 loop，统一队列负责消费者；接收回调不等待模型完成。
- `src/qwenpaw/app/channels/base.py`：对话输出最终经过渠道发送入口。
- `src/qwenpaw/app/channels/telegram/channel.py`：SDK handler 构造来源与路由信息后提交 `_enqueue`。

参考其职责拆分；保留 WorkFLowWeave 已有队列、命令端口、Workflow 发送和错误诊断，不照搬其静默超时/丢弃行为，不再增加一套渠道运行时。

## 2. 归属和身份

| 概念 | 含义 |
| --- | --- |
| 渠道能力 | `qq`、`telegram`、`feishu`、`wechat_openclaw` 等插件注册的类型 |
| 渠道实例 | 用户配置的具体资源 ID；同一种能力可以有多个实例 |
| Agent 对话 | AgentService 持有的 session、轮次和唯一事件日志 |
| 实例绑定 | 渠道侧保存 `channel_instance_id -> agent_session_id`，每个实例至多一个当前对话 |
| 平台来源/路由 | SDK 验证的好友、群、发送者、消息 ID 和回复地址；用于来源记录、去重和平台发送 |

绑定由渠道侧拥有和持久化，复用现有绑定存储；AgentSession 不保存 channel ID，不设置全局默认渠道。实例没有绑定时就是未绑定，不从第一条普通消息自动推断或创建对话。

两个 QQ 实例可以分别绑定两个对话。一个实例收到不同好友或群的消息，仍进入该实例绑定的同一个对话；不能继续按 sender/room 自动拆成多个 Agent session。平台来源信息必须保留，不能因此把回复发到另一个对端。

### 2.1 内存绑定与持久化顺序

实例的当前绑定由进程内缓存维护，启动时一次性从现有渠道 SQLite 加载。接收路由、查询当前绑定以及每次发送前的检查均读取内存，不逐条查询 SQLite，也不引入 Redis。SQLite 只保存绑定的恢复数据和已有请求证据；资源配置与 Agent 对话不增加另一份绑定。

所有缓存读写受同一个线程锁保护，返回不可变绑定快照。异步改绑另以写锁串行化，先在锁内更新内存，再写 SQLite；不跨数据库等待持有线程锁。改绑是低频操作，采用同步完成语义：成功响应等待持久化完成（通过 aiosqlite await，I/O 不阻塞事件循环）。高频的路由和发送只依据内存对话 ID 与版本，不增加逐次数据库校验或 Redis；用户接受内存短暂错误的取舍，不为此增加后台 writer、重试队列或额外一致性系统。持久化失败必须显式报错，恢复之前的内存对话并使绑定版本继续前进，回滚数据库事务；不能报告成功或让旧在途输出因为回滚而重新获得发送资格。请求等待被取消时，已开始的短数据库事务仍完成并保持写锁，随后传播取消；不能在 SQLite worker 可能已经提交后仅恢复内存，造成内存与重启恢复记录不一致。

绑定快照携带内部版本，解除、更换和失败恢复均使版本前进，用于检测排队输入与在途输出是否过期；对话 ID 改回原值也不能复活旧输出。该版本不进入 AgentSession，也不另建路由系统。

## 3. 接收、排队与指令

接收流程：

```text
SDK 收到消息
  -> 插件验证来源、保留可信平台路由
  -> ChannelManager 查渠道实例的绑定
  -> 使用已有命令分类确定优先级
  -> 提交到唯一队列
  -> 普通消息交给绑定的 Agent 对话；高优先级指令走指令通道
```

接收入口只负责提交，返回不表示 Agent 已完成，也不表示出站消息送达。消费者协程拥有后续 Agent 处理和发送；SDK 回调不等待完整 Agent 轮次，不另建后台模型调用或第二个队列。

移除 `enqueue(wait_result=...)` 布尔模式。Web 创建对话、发消息等接口若需要既有 Agent 操作结果，由 Web 适配层对队列请求结果进行投影；不能要求 SDK handler 使用同一模式等待 Agent。

未绑定的实例不能把普通消息提交给任意对话，也不能静默自动建对话。应明确暴露未绑定状态和消息未处理的原因，按平台能力报告错误。

保留已有命令分类和优先级语义：`/stop` 走独立高优先级通道，不能排在模型完成之后；`append/compact` 进入 Agent 既有安全边界；会话切换命令保留顺序屏障。显式切换对话的命令成功后更新渠道实例的绑定，失败不修改绑定；不从普通消息推断切换。

`/resume <session_id>` 校验目标 Agent 对话存在后，修改当前实例绑定；允许从未绑定状态绑定，也允许切换到此前未由该实例使用过的对话。不保留旧按平台对端的 ownership 限制。此版本采用简单改绑，后续更贴合实际使用的交互另行设计。

一个实例内的不同发送者共享同一绑定与调度范围，高优先级指令作用于该实例的对话。去重仍能区分平台消息来源，不能把不同对端恰好相同的消息 ID 误认为同一请求。

## 4. Agent 发送时确认绑定

Agent 只产生对话输出。渠道侧根据输出所属对话与实例绑定确定发送实例和可信目标；Agent 不传入自行选择的渠道、凭据或目标来覆盖路由。

每次外发前从加锁的内存缓存确认：实例当前仍绑定该输出所属的 Agent 对话，绑定版本与输出快照一致，并使用该实例的合法平台发送目标或此次输入保留的回复路由。这里的“确认”是程序检查绑定，和 Workflow 的平台投递结果是两个概念，不是向用户弹出批准请求。

绑定已经解除或改到其他对话时，旧输出不得发到新的对话路由，也不得猜测目标或静默切换渠道；记录明确的未发送原因。已经排队或开始处理的输入保留所属对话与路由，不能因界面重新绑定而转投另一对话。显式会话切换命令仍按队列屏障决定前后输入归属。

复用具体双向适配器的发送 API；普通发送和关联原消息的回复只在目标与关联参数上不同，共享客户端、凭据、平台 I/O 和错误处理。保留单一发送实现，不能为 Agent 另外实现协议或投递流水线。

## 5. Workflow 与单向发送

Email/file 等仅有 `notification` 能力的渠道用于 Workflow；不能绑定 Agent 对话或接收入站。当前不把它们直接加入 Agent 对话发送选项。

Workflow 继续使用现有“发送，然后等待发送回执”的通知设计、配置快照、超时和投递结果。等待的是 SMTP/文件/平台 API 的发送确认，不是收件人的回复或已读，也不是 Agent 的入站结果。

Workflow 选择 QQ/飞书/Telegram/微信等双向适配器作为通知目标时，直接调用该适配器已有发送 API；不要求绑定 Agent 对话、不创建对话、不启动接收，也不经过 Agent 队列。不为这种用途设计另一套发送协议或通知运行时。

Agent 对话回复和 Workflow 通知可以共用平台发送代码，但路由来源不同：前者由渠道实例的对话绑定及可信平台路由决定，后者由本次 Workflow 通知快照决定。

## 6. 前端绑定与 Web 调试

绑定入口位于双向渠道的实例配置/管理页面。每个实例显示当前绑定的对话，支持选择已有对话、更换和解除绑定；初始为未绑定。单向实例不显示对话绑定入口，Agent 创建页不增加“选择渠道”或全局默认渠道设置。

渠道管理 API 负责查询和更新绑定，验证实例支持双向能力以及目标对话存在。具体接口与存储布局在实施任务中确定；复用同一绑定来源，不能在资源配置和数据库各维护一个当前对话。

前端可从绑定入口打开对应 Agent 对话。绑定不限制 Web 的已有读取与调试入口：列表、历史、状态、事件/SSE 使用同一个 session 和同一份日志，无需复制一个 Web 对话。通过 Web 观察消息不会再次向外部平台发送。

Web 调试发出的消息和指令仍遵守 Agent 的单轮准入、命令分类与取消语义；Web 不另存平台绑定。其涉及的外发同样遵守第 4 节的发送时绑定确认。

## 7. 存量兼容和实施范围

旧按平台对端保存的多个对话，不可自动任选一个作为实例绑定。保存原对话、请求身份、去重证据及历史；由前端明确选择该实例的当前对话，未确认前显示未绑定。重启恢复实例绑定时仍核对目标对话，失败明确报告，不以新建对话掩盖丢失。

用户已授权实施此简单版本。实现与验证记录于 [tasks.md](tasks.md)；进一步的使用体验调整不扩展到本轮。

# 任务与决策依据

依据：用户要求直接添加 Cursor 风格 MCP JSON，并明确“点击编辑 Json，默认不采用这个”；示例中的 `servers.qqmusic-mcp` 是本次验收输入。沿用现行 [MCP 运行时契约](../collect-from-mcp-and-cli/specs/mcp-runtime/spec.md) 的稳定服务身份、现有 `MCPServerConfig` 和资源仓库原子发布边界；不修改既有 design 决策。

## 任务

- [ ] 1. 增加 Cursor 包络解析模型与名称到内部服务身份的转换，覆盖 `servers`、`mcpServers`、`type: stdio` 和连字符名称。
- [ ] 2. 增加原子批量导入 API，拒绝重复名称和明文凭据越界，保留现有单条 MCP API。
- [ ] 3. 在 MCP 服务编辑器增加默认字段模式与显式 JSON 模式，提交示例后调用导入 API；列表和来源选择器继续使用同一名称身份。
- [ ] 4. 补充后端模型/API 与前端单元测试，验证无效 JSON、部分失败不落盘和默认模式。
- [ ] 5. 运行定向测试、类型检查、Ruff、前端构建和最小 HTTP 验收，记录实际结果。

## 默认值与取舍

- JSON 编辑默认关闭：这是用户明确要求；现有字段表单继续承载常规单条编辑，避免强迫所有用户学习包络格式。
- `type` 省略按 `stdio` 处理：Cursor 的本地进程配置以 stdio 为默认语义，且不改变现有 MCPServerConfig 的 `stdio` 默认创建值。
- 导入接口使用原子批量发布并拒绝重复名称：批量配置任一项失败时保留旧资源，避免用户得到半套 MCP；覆盖同名资源需要明确走现有编辑/replace 流程。
- 明文 `env` 不转换为凭据：现有运行时只接受环境引用或加密凭据，静默保存明文会破坏安全边界；本次示例不包含该字段。

# 数据源中心配置演示交付

## 授权与范围

- 依据后续用户指令：撤回“采集器实例 + 处理模板”两类对象的页面拆分，以已有数据源为中心；在数据采集处支持新增、加载、保存和脱离共享设置；资源配置中心的修改同步到仍使用共同设置的位置；单个工作流要单独修改时先脱离，唯一共同使用位置可以直接保存；面向非专业用户，并制作前端交互 demo。
- 本记录承接原方案，但只实现演示页面，不改后端数据模型、API 或采集运行语义。
- 不修改总 `proposal.md` / `design.md` 或原有 `spec.md`。原方案仍保留作历史上下文，本记录标明后续演示采用的交互决策；产品化前需要依据最新用户要求另行更新正式设计。
- 临时 AxonHub 凭据仅用于用户本地浏览器会话，不写入仓库。

## 决策与依据

- 页面唯一配置对象使用“数据源”，采集器类型只作为数据源的来源能力；“取到后怎么整理”属于该数据源的一部分，普通界面读写结构化选项，高级模式继续编辑同一份 JSON。依据用户明确要求以原有数据源为中心并保留高级模式。
- “新增采集器”从数据采集处创建后加入当前工作流；“加载采集器”只把资源配置中心已有数据源加入工作流，两个入口不复制出第二份全局资源。资源配置中心新增数据源不自动加入当前工作流。
- 工作流数据采集中的共同配置只允许在唯一工作流仍跟随共享设置时直接保存。多个工作流仍跟随时必须先脱离；脱离产生当前工作流的本地覆盖，恢复共同设置删除该覆盖并重新继承数据源。
- “同步到 N 个工作流”按仍跟随共同设置的工作流数显示，已经脱离的工作流不计入同步范围；总体引用位置另行用于展示使用位置。该区别直接来自用户给出的同步/脱离语义。
- 本次只演示名称、来源位置、可选密钥、读取数量、启用状态及常用处理规则；模板版本、真实采集预览、后端持久化和批量迁移继续留待后续版本，符合用户“不要写得太复杂”的范围要求。
- 现有 `SourceConfig` 包含 `collector`、`options`、`setters`、`template` 和运行策略，`SetterTemplate` 单独存储 JSON 规则；演示不宣称已经改变此后端契约，只表现用户要求的简化交互。

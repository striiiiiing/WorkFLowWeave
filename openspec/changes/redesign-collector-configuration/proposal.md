# 采集器实例与处理模板前端重设计

## Why

当前前端把采集器类型、采集器实例、实例参数、处理规则和模板引用放在同一个表单中。用户需要理解 `collector`、`options`、`setters` 和 `template` 等内部字段，才能完成一次配置。

对于不了解系统内部模型的用户，页面没有清楚回答两个问题：

- 采集器实例负责什么配置；
- 处理规则如何复用，以及能用于哪些采集器。

参考 AxonHub 的“配置时选择模板、右上角统一管理模板”交互，将采集器页面改为以采集器实例为主体，并把处理模板集中管理。

## What Changes

- 采集器页面主要展示采集器实例，右上角提供“处理模板”和“新增实例”。
- 采集器实例负责采集器级配置，例如地址、Key、账号、默认范围、启用状态和超时策略。
- 处理模板负责采集结果的 JSON 处理规则，例如字段选择、过滤、排序、分组和格式化。
- 每个处理模板绑定一个指定的采集器类型，只能被同类型的采集器实例或工作流使用。
- 采集器实例和处理模板支持独立的显示名称；没有显示名称的旧资源继续使用内部 ID 展示。
- 保留原有高级模式，可直接查看和编辑处理规则 JSON。
- 保留现有实例局部规则和工作流局部覆盖能力，但在普通界面中隐藏内部字段名。
- 本期不增加模板版本、发布/回滚、导入导出、跨采集器转换或生效结果预览。

## Capabilities

### Modified Capabilities

- `frontend`：重组采集器实例、处理模板和工作流采集配置的交互。
- `configuration`：为采集器实例和处理模板增加可选显示名称，保持旧资源兼容。

### Unchanged Capabilities

- Collector 的插件注册和单来源执行；
- Setter JSON 的数据结构与校验；
- Workflow 的执行顺序、快照和运行时合并语义；
- 现有资源 API 路径。

## Impact

影响前端资源中心、采集阶段配置、资源 DTO 类型和配置模型。处理模板仍使用现有 `SetterTemplate` 存储，不新增独立存储系统或第二套规则格式。

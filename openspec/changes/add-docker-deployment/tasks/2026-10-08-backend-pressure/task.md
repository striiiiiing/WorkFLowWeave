# 后端低频负载与短时压测

## 依据与范围

- 用户要求实际压测后端，并将结果写入 README；随后指定可以使用 `ssh myserver`，原低配服务器已不可用，再要求优先保证远端稳定。
- 参考本变更 `proposal.md` / `design.md` 的单进程生命周期和真实健康检查，不修改设计、产品代码、远端配置或生产数据。本项是实验与文档任务，不是代码缺陷修复。
- 既有 `artifacts/deployment-20261008` 是 2 vCPU / 1,608 MiB 机器的固定轻负载证据；本轮 `myserver` 为 4 vCPU / 7,948 MiB、存在 swap 和多项共用服务，必须分别报告，不能当作专用低配机器。
- 只读 `/api/health`、`/api/sources`、`/api/plugins`，通过远端 localhost 避免将 SSH/WAN 延迟混入 API 延迟。未测工作流、AI、工具和通知，不声明这些业务容量。
- 日常负载默认 4 客户端、每客户端每 0.5 秒发一次请求（合计约 8 req/s），是明确的实验负载，不能由 `max_concurrent_runs=4` 推导 API 并发限制。30 秒空闲、60 秒低频采样用于观察短时日常开销，不声明长期稳定性。

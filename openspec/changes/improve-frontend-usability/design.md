# 设计

依据用户对 F04/F07/F08/F12 的明确要求与审核报告，建立新的实现设计；原提案及设计保持原样。

## 报告阅读

页面以历史工作流名称为标题，首先显示运行状态、开始/结束时间、失败原因。优先展开最终报告和通知状态，采集与分析为可展开的过程细节。每个阶段分别加载，单阶段读取失败有重试入口。所有正文请求固定使用页面展示的同一 session version；版本变化时清理旧正文，不读取当前配置补充历史事实。

解析 `stages.py` 已有的 collection、analyses、outputs、deliveries 和 finish 字段；正文用安全 Markdown 渲染（禁用 HTML，不执行插件脚本）。通知保留“未发送”“投递失败”“结果不确定”的区别。没有阶段记录、主动不保存、过期、文件缺失、损坏和写入失败分别说明，终态未执行的阶段不显示为运行中。原始 JSON、运行编号及版本仅在高级模式下显示。

插件可在 CollectorOutput 的可选 `report` 字段提供有类型的 sections：text（正文）、metrics（标签/值/单位）和 table（列标题及标量单元格）。后端验证种类、必填内容、表格列数；声明与结果一起存档。旧插件不必声明，依然显示标准 text。扩展仅负责展示，不改变 count/status、AI 输入或错误事实。未知/损坏结果明确显示无法解析并提供高级数据，不能猜测成功。

## 恢复资格

抽出 WorkflowService 原有的恢复材料检查，查询接口与实际恢复共用；检查 checkpoint、快照、引用正文及运行准入。只读查询返回可恢复与具体原因，前端据此显示按钮；真正恢复时重新检查。保留后端原有可恢复状态范围，不以浏览器枚举状态代替恢复判断。

## 参数与编号

Ajv 保持唯一 JSON Schema 验证器。UI 解释局部引用与组合类型以决定控件，不能把引用字段误显示为任意类型。根验证始终保留全部约束。切换插件时清理旧 options/setters/template，异步加载元信息不能清理正常草稿。

插件前缀可选，允许既有编号字符，最多 43 字符（80 总长减 36 位 UUID 减一个下划线）。生成前缀_UUID；无前缀生成 UUID。普通界面显示编号，用户可修改或去除前缀；不增加对用户编号的前缀校验。

## 绑定与其他交互

任务编号禁止重名，只有合法唯一的改名才更新汇总引用。汇总开关保存本次编辑中的草稿。通知绑定允许填写插件声明的工作流参数。已绑定停用资源仍显示停用状态并保留覆盖，不能新增选择停用资源；执行阶段跳过停用资源，再启用后可继续调用。SMTP 凭据复用已有环境变量/加密凭据方式。

保存时仍校验所有绑定，包括停用项，避免重新启用时出现无效配置；过滤只发生在执行快照中。所有数据来源均停用时允许保留配置，但运行明确返回 `workflow_no_enabled_sources`（HTTP 409），提示至少启用一个来源。这沿用工作流至少需要一个来源的模型约束，不回退执行已停用来源。

总览分项加载、插件诊断完整呈现，历史查询增加开始时间范围，窄屏记录使用卡片。API 校验错误映射为可读字段路径，不复制业务规则。

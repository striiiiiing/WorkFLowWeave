# 文件引用采集设计草案

## Context

需求与范围见 [proposal.md](proposal.md)。用户于 2026-10-10 要求先编写 OpenSpec 再实施；本文件是本次新增设计草案，尚不代表实现完成，也不修改任何既有 design.md。

当前 `SourceConfig.call` 使用 MCP/CLI 联合类型；`CollectorInvocation` 与 Workflow 均调用 `CollectorManager.collect`。`SystemConfig.data_dir` 默认是 `data`，Docker bootstrap 使用 `/var/lib/workflowweave/data`。Workflow 已把获取原始结果和输入视图分开，并按存档策略保存运行事实。

本次是跨模型、API、文件存储、前端和部署的结构性新增。核心不变量是：**来源持久化的是文件引用；每次实际采集读取当时的文件；一次采集取得的正文与该次运行的处理结果对应。**

## Goals / Non-Goals

提供统一的文件引用模型，使导入文件和在线文本落盘后使用同一条读取链。引用文件独立于应用代码和镜像，用户可直接修改。

本次不实现图片/DOC/PDF 解码、任意编码自动探测、文件内容编辑器、目录浏览器、内容版本控制、hash 校验、文件监视或正文缓存。用户直接维护已有文件，网页负责导入、新建文本和配置引用。

## Decisions

### 1. 文件作为独立来源分支

在既有 `SourceCall` 中增加以下分支，沿用当前普通联合，避免重新引入嵌套 OpenAPI discriminator 问题：

```json
{
  "kind": "file",
  "file_type": "text",
  "path": "notes/2026-10-10_14-30-05_UTC+08-00_a1b2c3d4.txt"
}
```

`file_type` 为必填的显式类型，当前唯一合法值为 `text`；不根据扩展名或 MIME 自动推断类型。以后增加类型时扩展文件类型与读取实现，不新增导入来源和在线文本来源两套配置。

`path` 是相对于引用根目录的路径；不存绝对路径、正文、内容 hash、文件大小或 mtime 作为引用有效性的条件。导入/在线输入只是创建文件的方式，不是运行时的另一种来源。已有文件可以直接填写相对路径引用，无需再次上传。

文件来源沿用 `enabled`、`timeout`、`limits`、`on_error`、`on_empty`。公共调用不接受 MCP `arguments` 覆盖；使用与 CLI 一致的空参数 schema，非空覆盖明确报错。

仅用 CLI `cat` 的小补丁无法覆盖网页保存、文件类型与统一路径语义，而且会引入命令依赖；因此增加文件分支，而不是生成 CLI 命令。

### 2. 单一引用目录与文件服务

引用根目录固定派生自 `SystemConfig.data_dir`：`<data_dir>/references/`，不增加第二个应用级根目录配置。创建 `collection` 所属的文件服务，由生命周期注入采集管理器和 HTTP 接口；存储路径解析及文本编码规则只有一个实现。

路径校验适用于写入和每次读取：拒绝空路径、绝对路径、路径越界、NUL 和解析后逃逸引用根目录的符号链接。路径校验落实用户要求的相对路径范围，不能把本接口变成对数据库、密钥或应用代码的任意读写。目录、特殊文件和不可读取文件明确失败。用户可以填写子目录，创建文件时创建缺失父目录。

保存来源只验证引用结构与路径边界，不预读正文，不要求文件必须已经存在。不存在的文件在实际采集时报告错误；这样外部文件的创建、修改或删除不需要触发资源配置更新。

### 3. 文本创建与导入 API

所有路径以 `/api` 为前缀。创建成功返回可直接用于 `SourceConfig.call` 的文件引用，HTTP 201，响应带 `Cache-Control: no-store`。

| API | 输入 | 行为 |
| --- | --- | --- |
| `POST /collection/files/text` | JSON：`path`、`file_type: "text"`、`text` | 将正文按 UTF-8 写入用户指定相对路径。 |
| `POST /collection/files/import?path=...&file_type=text` | `application/octet-stream` 原始文件字节 | 验证为 UTF-8 文本后，原样保存文件字节。 |

两种 API 共享创建文件的实现，路径已存在时返回 HTTP 409 `file_conflict`，不覆盖、不自动改名。写入使用同目录临时文件，完整写入后以不覆盖目标的原子方式发布；写入或发布失败清理本次临时文件，不暴露半成品。

非法类型、编码或路径返回明确的参数/路径错误；权限、磁盘等 I/O 失败返回明确存储错误。空文本和空文件合法，运行时按 `on_empty` 处理。保留正文空白与换行，不 trim，不将 CRLF 自动转换为 LF。导入接口使用字节上传，避免浏览器 `File.text()` 对非法 UTF-8 的替换掩盖编码问题；不引入 base64 或额外 multipart 依赖。

创建文件与保存来源是两个明确步骤。文件创建失败时不保存引用；文件已创建而来源保存失败时保留文件并显示错误，前端保留成功创建的引用供重试，避免重试时再次创建同一路径。此处仅保存提交状态，不缓存运行时文件内容；不自动删除用户可能已经修改的文件。

### 4. 运行时读取与 Workflow 接入

`CollectorManager.collect` 的文件分支通过注入的文件服务读取，阻塞文件 I/O 离开事件循环。每次调用都重新打开文件并严格按 UTF-8 解码，不通过缓存、mtime 或 hash 决定是否读取；文件缺失、非法编码和 I/O 异常产生明确失败，超时沿用来源超时状态。

文件原始结果使用 `{"text": "本次读取的正文"}`，获取元数据标明 `kind`、`file_type`、相对 `path` 和已知结果状态；不伪造 CLI stdout/退出码或 MCP 信封。

Workflow 的内容提取对文件结果读取 `raw.text`，与 CLI 文本共用严格 JSON 识别及后续格式/预算处理。空字节文件为空结果；`0`、`false`、`null`、`[]`、`{}` 和仅有空白的非空文件不按真假值判空。原始结果与输入视图分开保存。

新运行、显式从采集阶段重跑、直接调用采集 API，都在实际执行该来源时重新读盘。已经采集完成的同次运行继续分析或重试输入处理，使用该次获取结果；历史报告不因外部文件修改而改变。既有存档是运行事实，不作为未来采集的缓存。若希望历史恢复使用修改后的文件，应显式重跑采集阶段；本次不改变 MCP/CLI 的恢复语义。

### 5. 前端表单与默认文件名

在「来源方式」的 MCP、CLI 之后加入「文件引用」。选择后展示必选的「文件类型」，初始未选择，当前只提供「文本」；提交时必须有合法类型，不能由扩展名隐式填入。

默认未勾选「输入文本」，展示浏览器文件选择控件。勾选后展示多行正文输入。两种方式都展示相对保存位置；已有文件可只填写路径引用。在线文本仅在新建/提交时发送，不在重新打开来源编辑器时加载正文。

浏览器生成默认路径：

```text
2026-10-10_14-30-05_UTC+08-00_a1b2c3d4.txt
```

时间的年月日时分秒使用浏览器本地时间，`UTC+08-00` 是该时间点浏览器时区的 UTC 偏移，西区使用如 `UTC-05-00`；按时间点计算偏移以覆盖夏令时。随机部分取浏览器密码学随机 UUID 的 8 个十六进制字符，降低同秒碰撞；后端仍通过独占创建保证不覆盖。

文件名不使用文件系统不兼容的冒号或时区名中的 `/`。用户可修改路径与文件名；切换输入方式不重置已填路径。已有引用编辑时保留原路径，不生成新名字。默认 `.txt` 只是新建文本的文件名建议，不参与类型判断。

来源摘要显示文件类型和相对路径，搜索包含路径。工作流内编辑与共享资源编辑复用同一表单和 API。

### 6. Docker 外部目录

本地默认目录为 `data/references/`。Docker 继续使用既有 `state` 卷保存配置、数据库和密钥，新增子目录 bind mount：

```yaml
services:
  backend:
    volumes:
      - ./data/references:/var/lib/workflowweave/data/references
```

挂载与现有父状态卷同时存在，只覆盖新功能所属子目录。Docker 文档说明宿主目录准备、uid 10001 写权限，以及宿主 `data/references/notes/example.txt` 对应来源 `path: "notes/example.txt"`。不把引用文件复制进镜像。

自定义 `data_dir` 的部署需把挂载目标改为实际 `<data_dir>/references/`；应用始终从 `data_dir` 推导，不另读 Docker 路径配置。当前尚无该功能的历史文件需要迁移；已有部署若提前放入同名子目录，启用 bind mount 前应将其中的文件复制到宿主目录，避免挂载遮蔽原文件。

## Risks / Trade-offs

- 外部程序在采集读取期间写入文件，可能产生该时刻可见的内容或明确读取错误；不增加文件锁、hash 或内容版本。需要完整更新时由用户在宿主机原子替换文件；系统不承诺多个来源间的文件系统快照一致性。
- UTF-8 以外的文本导入/读取会明确失败；本次不自动猜测编码，避免乱码被保存为成功结果。
- 文件创建与来源保存不属于同一事务；按第 3 节保留已创建文件和提交状态，避免自动清理误删外部修改。
- bind mount 的宿主权限可能导致写入失败；文档给出实际容器 uid 的权限准备方式，应用直接报告错误，不回退到镜像内目录或另一处存储。
- 用户修改文件后，新采集使用新内容，旧报告保留当时内容；必须在 API 与测试中保持这个边界，不能以重读文件来伪造旧运行恢复。

## Migration Plan

新增文件来源模型与服务后接入 HTTP、Workflow 和前端；不重写已有来源，也不提升资源格式版本。部署时准备外部子目录并加入挂载，验证保存、外部修改、再次采集及容器重启后的读取。

回退旧版本前需删除或改回所有共享来源、工作流独立来源中的 `kind: "file"` 配置；旧版本不能解析新增分支。已有含文件来源的历史快照也需要新版读取，不宣称旧版兼容；引用文件本身保留在宿主目录，不随回退删除。

# 前端重构连续性验收

依据：[已授权架构设计](../../../design-frontend-architecture/design.md) §5、§6、§8；既有报告、恢复、移动端和 Schema 要求保持其所属规范。这里只补充尚未形式化的可观察约束。

## ADDED Requirements

### Requirement: 查询刷新不覆盖正在编辑的草稿

前端 SHALL 在一个工作流编辑会话中维护一份工作流草稿；目录刷新和四阶段切换不得替换尚未保存的修改。资源表单和高级 JSON SHALL 编辑同一领域值，非法 JSON SHALL 保留原文本并阻止提交。

#### Scenario: 目录刷新与阶段切换

- **WHEN** 用户修改来源、分析或通知配置后刷新资源目录并切换阶段
- **THEN** 未保存修改仍保留，绑定与引用保持一致，刷新失败显示错误

#### Scenario: 非法高级 JSON

- **WHEN** 用户输入不能解析的高级 JSON 并尝试保存
- **THEN** 系统保留输入并显示校验失败，不将其改为空对象或提交

### Requirement: 数据源保存范围明确且兼容历史配置

前端 SHALL 明确区分写入共用资源与只修改当前工作流的独立配置；脱离共享 SHALL 使用后端解析后的完整配置，既有模板引用继续由后端解析，正式界面不恢复独立模板 CRUD。该要求承接已授权设计 §2.1、§6 引用的正式接入决策。

#### Scenario: 保存独立配置

- **WHEN** 用户在工作流中修改独立数据源配置
- **THEN** 修改仅进入工作流草稿，保存工作流后生效，不写共用数据源

#### Scenario: 共用资源成功而工作流未保存

- **WHEN** 用户发布或修改共用数据源成功但尚未保存工作流
- **THEN** 页面刷新受影响目录并分别表达两种保存状态，不宣称它们原子保存成功

#### Scenario: 查看使用位置失败

- **WHEN** 使用位置查询失败
- **THEN** 显示使用情况未知，不显示为零个引用；查询成功时当前草稿替换其服务端快照且不重复计数

### Requirement: 同屏查询具有一致快照和独立失败状态

前端 SHALL 让同屏消费者使用同一查询快照并在保存后显式刷新对应查询；总览各查询 SHALL 独立保留读取时间、上次成功结果和失败状态。

#### Scenario: 健康结果共享

- **WHEN** 首页同时展示健康指标、告警和诊断
- **THEN** 它们使用同一次健康查询的有效结果，不各自重复请求

#### Scenario: 刷新失败保留事实

- **WHEN** 同一身份的查询刷新失败
- **THEN** 原有结果可保留且同时显示失败；实体身份改变时不显示旧实体结果，查询失败不伪装成数量零

### Requirement: HTTP 失败和写入未知结果可辨认

前端 SHALL 保留服务端错误状态、错误码、详情及请求路径；204 SHALL 作为无内容成功，其他 JSON 接口的成功回包 SHALL 严格解析。取消、网络失败、协议错误及业务失败 SHALL 可区分，未知写入结果不得自动重发。

#### Scenario: 健康接口返回 503

- **WHEN** 健康接口返回 503 的合法健康报告或结构化错误信封
- **THEN** 合法报告可显示，错误信封显示为失败，其他端点的 503 不作为成功

#### Scenario: 非 JSON 错误和无效成功内容

- **WHEN** 接口返回非 JSON HTTP 失败或无效 JSON 成功回包
- **THEN** 前者保留原 HTTP 状态与路径诊断，后者显示协议解析错误，不伪造成功数据

#### Scenario: 写入响应丢失

- **WHEN** 保存或运行操作已提交但连接断开而结果未知
- **THEN** 保留用户输入和错误状态，不自动重放有副作用请求

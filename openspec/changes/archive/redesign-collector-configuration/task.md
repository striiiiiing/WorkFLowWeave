# 采集器实例与处理模板前端重设计任务记录

状态：方案已记录，尚未实施。

## 用户确认

- 同意为采集器实例和处理模板增加独立显示名称。
- 保留原先高级模式能力，可以直接查看和编辑处理规则 JSON。
- 参考 AxonHub 的交互：在采集器页面右上角统一管理模板，配置时加载模板。
- 模板必须限制在指定采集器类型内。
- 本期控制范围，模板版本、发布、回滚、导入导出和复杂预览留到后续版本。

## 依据

- `SourceConfig` 是当前可复用的采集器实例模型，保存 options、template、setters、启用状态和失败策略。
- `SetterTemplate` 是当前可复用的处理 JSON 模板，已经带有 `collector` 归属。
- `CapabilityDescription` 提供 options/setters Schema，`x-logagent-workflow=true` 可区分实例配置与工作流配置。
- `resolve_source_call` 已定义实例模板、实例局部规则、工作流模板和工作流局部规则的合并顺序；前端不复制该业务逻辑。
- 当前前端的 `ResourceEditor`、`SetterTemplateManager` 和 `SourceStepCard` 将这些概念混在同一层，方案只调整交互表达和资源显示，不改变采集执行模型。

## 默认值与取舍

- 模板默认绑定采集器类型，而不是单个实例：沿用现有 `SetterTemplate.collector`，同时允许同类型实例复用。
- 没有模板时继续允许直接编辑局部 JSON：保持当前高级模式能力，避免阻断已有配置。
- 旧资源缺少显示名称时回退到 ID：不强制迁移、不因打开页面改变运行配置。
- 新增显示名称为可选字段：保留现有资源 API 和内部 ID 引用，降低兼容风险。
- 不新增模板版本、发布或预览默认行为：这些能力需要额外的版本与生效语义，留给后续变更。
- 不改变超时、失败策略、并发和备份默认值：避免本次 UI 重设计引入运行行为变化。

## 实施边界

- 允许修改新变更涉及的配置模型、前端 DTO 和前端页面。
- 不修改现有总 proposal、总 design 或已完成模块设计。
- 不新增第二套模板 JSON 格式。
- 后端仍是资源引用、Schema 和类型匹配的最终事实来源。

## 验证要求

- 右上角模板管理可以新建、编辑、删除和按采集器类型筛选模板。
- `logs` 模板不能被 `history` 实例选择或保存。
- 实例局部规则不会修改共享模板。
- 工作流局部规则不会修改实例或共享模板。
- 高级 JSON 编辑在语法错误和后端校验失败时保留用户输入。
- 没有显示名称的旧资源仍能加载、编辑和保存。
- 缺失或不兼容的模板引用显示警告，不静默清空。
- 375px 视口下实例列表、模板入口和编辑窗口仍可操作。

# 设计

## 1. 核心概念

```text
采集器类型（插件能力）
        │
        ├── 采集器实例（连接与采集配置）
        │       └── 默认处理模板
        │
        └── 处理模板（指定采集器类型的 JSON 规则）

工作流可以选择采集器实例，并对本次运行增加局部覆盖。
```

### 1.1 采集器类型

采集器类型来自插件能力目录。它提供 `options_schema`、`setters_schema`、字段和说明，不作为用户创建的资源保存。

`options_schema` 中未标记 `x-workflowweave-workflow=true` 的字段属于实例级配置；标记了该值的字段属于工作流调用级配置。前端只负责按 Schema 分区展示，最终校验仍由后端完成。

### 1.2 采集器实例

采集器实例对应现有 `SourceConfig`，用户可以把它理解为“一个已经配置好的数据来源”。实例负责：

- 显示名称和内部 ID；
- 采集器类型；
- 插件声明的连接、认证和默认采集范围；
- 启用状态；
- 超时及来源失败策略；
- 默认处理模板和实例局部规则。

当前插件没有实例级参数时，页面显示“此采集器没有需要填写的连接配置”，不要求用户填写无意义的 JSON。

### 1.3 处理模板

处理模板对应现有 `SetterTemplate`，保存一份与采集器类型绑定的 JSON 处理规则。规则可以表达字段选择、过滤、排序、分组和格式化，具体可用字段由该采集器的 `setters_schema` 决定。

模板绑定的是采集器类型，而不是某一个实例。例如 `logs` 模板可以被多个 `logs` 实例使用，不能被 `history` 实例使用。创建、编辑和选择时都必须执行这一限制。

普通模式使用现有 Schema 表单；高级模式继续编辑同一份完整 JSON，不维护两套数据来源。

## 2. 页面与交互

### 2.1 采集器实例页面

页面以实例列表为主体，顶部提供：

```text
采集器实例                         [处理模板] [新增实例]
```

实例列表优先展示显示名称、采集器类型、启用状态和默认处理模板。内部 ID 放在高级信息中；旧资源没有显示名称时回退显示 ID。

点击“新增实例”进入实例编辑；点击“处理模板”打开统一模板管理窗口，不要求用户先选择某个实例。

### 2.2 实例编辑

编辑顺序为：

1. 填写实例名称；
2. 选择采集器类型；
3. 填写“连接与采集设置”；
4. 选择默认处理模板；
5. 在“处理规则”区域调整实例局部规则；
6. 在高级设置中调整启用、超时和失败策略；
7. 保存。

选择采集器类型后，模板选择器只显示同类型模板。切换类型时保留现有的显式确认行为：确认后清空与旧类型相关的 options、规则和模板引用；异步加载能力信息不能清空正常草稿。

### 2.3 右上角统一模板管理

模板管理窗口提供：

- 当前模板列表；
- 按采集器类型筛选；
- 新增模板；
- 编辑模板；
- 删除模板；
- 关闭窗口。

新增或编辑模板时先选择“适用采集器”，再填写名称和规则。保存前显示适用范围，例如“可用于所有 logs 采集器实例”。不提供跨类型模板选择。

模板编辑窗口保留“普通表单 / 高级 JSON”切换。高级 JSON 的语法检查和后端 Schema 校验沿用现有能力，错误不能被转化为空规则。

### 2.4 实例中的模板加载

实例编辑器中的处理规则区域提供“加载模板”：

- 只列出当前采集器类型的模板；
- 选择模板后显示模板名称和适用采集器；
- 未选择模板时，可以直接编辑实例自己的规则；
- 修改实例自己的规则时，提示这是局部调整，不会修改共享模板；
- 已有局部调整时，明确提示其会覆盖模板中同名字段。

本期不提供独立的“脱离模板并复制完整规则”流程；用户可以清空模板引用后继续使用高级 JSON 编辑能力，具体复制和预览能力留到后续版本。

### 2.5 工作流中的使用

工作流采集卡片显示实例名称、采集器类型、启用状态和默认模板。默认行为是继承实例配置。

用户打开“本次调整”后，可以选择同类型处理模板或编辑当前工作流的局部规则。保存只更新 `source_overrides`，不会修改实例或共享模板。

## 3. 配置合并与兼容

沿用后端当前合并语义，不在前端复制业务合并逻辑：

1. Schema 默认值；
2. 采集器实例 options；
3. 采集器实例模板；
4. 采集器实例局部 setters；
5. 工作流调用 options；
6. 工作流模板；
7. 工作流局部 setters。

显式空列表和空对象仍然是用户输入，不能被前端转换为“未设置”。模板和实例必须属于同一采集器类型；失效引用保留并显示警告，不静默删除。

新增 `display_name` 为可选字段：

- 新资源建议填写显示名称；
- 旧资源没有该字段时使用 ID；
- 显示名称不要求全局唯一；
- API 引用和 Workflow 保存仍使用内部 ID；
- 读取旧资源时不自动写回名称。

删除被引用的模板由后端引用校验决定；前端显示后端返回的具体原因。

## 4. 本期边界

本期只解决“看得懂、选得到、用得对”的配置流程。以下内容留到后续版本：

- 模板版本、发布、回滚和变更历史；
- 模板导入、导出和跨采集器转换；
- 多模板叠加和复杂优先级编辑器；
- 生效 JSON 预览和样例数据试运行；
- 批量迁移旧资源名称；
- 按实例授予模板使用权限。

不新增超时、重试、并发或备份默认值，继续沿用现有模型和前端默认值。

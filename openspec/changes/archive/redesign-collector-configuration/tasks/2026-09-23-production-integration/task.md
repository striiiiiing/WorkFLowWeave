# 工作流设计与数据源中心正式接入

## 依据与范围

- 依据本轮用户要求：“把工作流设计展示实际放到工作流管理的编辑中；资源管理中心则以类似方式放在资源配置的数据源中，并去掉处理模板。”
- 承接 `../2026-09-23-data-source-centered-demo/task.md` 的数据源中心、共享与脱离决策，以及当前 `CollectorDesignDemoView.vue` 的四阶段导航、数据源卡片和编辑抽屉。
- 参考 `../../design.md` 的 Schema 驱动表单、单一配置来源与既有兼容要求；其中独立处理模板入口已由后续用户要求取代。本次只更新任务记录，不修改 proposal.md / design.md。
- 结构性接入：正式页面通过真实 API 保存；演示内存样例不迁入生产数据。采集参数和规则取自已注册插件，不展示演示中无后端支持的 Cron、任意抽取等功能。

## 决策与不变量

- 根据 2026-09-24 用户截图反馈，移除编辑页内重复的工作流列表和新建入口，选择与新建统一保留在外层“工作流管理”；编辑内容使用全宽布局。
- 工作流编辑使用四阶段导航与全览，切换阶段保留同一份工作流草稿；刷新资源目录不重置草稿。默认全览延续原正式页面四阶段同时可见的行为。
- 资源中心和工作流共用同一个数据源编辑器，基础信息、采集参数、整理规则及高级运行策略分组；保留结构化输入和 JSON 编辑及凭据保护。
- 共用配置由 SourceConfig 唯一持有。真正脱离使用 SourceOverride.source 保存完整独立配置，避免稀疏覆盖在资源中心新增字段后继续继承。旧 options/setters/template 覆盖保持原语义，不将其误称为完整脱离。
- 解析、展开旧模板及独立配置选择均由后端现有 resolve_source_call 路径负责，前端不复制合并规则。编辑已有配置时读取解析结果，保存后处理规则属于数据源本身；移除界面模板 CRUD，不删除历史模板资源和旧引用。
- 工作流中多个使用位置仍共享时，先脱离再单独编辑；唯一共享位置可直接保存共用配置。资源中心明确显示同步范围和使用位置；已脱离工作流不计入同步范围。
- 新增可选 display_name 和 description；旧数据源名称回退现有 ID。采集超时、并发、失败策略继续使用 models.py / domain/resources.ts / domain/workflow.ts 原默认值，不引入演示中的新默认限制。

# 前端采集器配置

## ADDED Requirements

### Requirement: 采集器配置按实例和模板分层

界面 SHALL 以采集器实例为主要资源，并在右上角提供统一的处理模板管理入口。采集器类型、采集器实例和处理模板不得以同一个技术表单概念展示。

#### Scenario: 查看采集器实例

- **WHEN** 用户打开采集器页面
- **THEN** 页面首先展示采集器实例，并提供“处理模板”和“新增实例”操作

#### Scenario: 打开模板管理

- **WHEN** 用户点击“处理模板”
- **THEN** 可以统一查看、新建、编辑和删除处理模板，不需要先进入某个实例

### Requirement: 处理模板限制采集器类型

界面 SHALL 使每个处理模板绑定一个采集器类型，并且实例和工作流只能选择与当前采集器类型匹配的模板。后端 SHALL 继续执行最终校验。

#### Scenario: 选择匹配模板

- **WHEN** 用户为 `logs` 采集器实例选择模板
- **THEN** 选择器只显示适用于 `logs` 的模板

#### Scenario: 选择不匹配模板

- **WHEN** 用户尝试将 `history` 模板用于 `logs` 实例
- **THEN** 前端不提供该选项，后端也拒绝不匹配的提交

### Requirement: 保留高级 JSON 能力

界面 SHALL 同时提供 Schema 表单和高级 JSON 编辑。两种模式 SHALL 编辑同一份处理规则，不能产生两个独立的规则来源。

#### Scenario: 编辑模板 JSON

- **WHEN** 用户在高级模式修改处理模板
- **THEN** 保存时检查 JSON 语法并提交给后端 Schema 校验，失败时保留用户输入

#### Scenario: 修改实例局部规则

- **WHEN** 用户修改实例自己的规则
- **THEN** 界面提示该规则只覆盖当前实例，不修改共享模板

### Requirement: 工作流覆盖作用范围清晰

界面 SHALL 显示工作流默认继承采集器实例配置，并区分本次工作流覆盖与共享模板。

#### Scenario: 工作流继承默认模板

- **WHEN** 工作流没有指定处理模板或局部规则
- **THEN** 本次采集沿用实例的默认模板和实例规则

#### Scenario: 工作流调整处理规则

- **WHEN** 用户在工作流中选择模板或修改局部 JSON
- **THEN** 只更新该工作流的 `source_overrides`，不修改实例和共享模板

### Requirement: 旧资源显示兼容

界面 SHALL 兼容没有显示名称的旧采集器实例和处理模板，并保留原有模板引用及局部规则。

#### Scenario: 旧资源没有显示名称

- **WHEN** 后端返回没有 `display_name` 的资源
- **THEN** 界面使用内部 ID 作为后备名称，并允许继续编辑和保存

#### Scenario: 模板引用失效

- **WHEN** 已保存资源引用的模板缺失或类型不匹配
- **THEN** 界面显示明确警告，不静默清除引用或伪装成未使用模板

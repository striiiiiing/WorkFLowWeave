# 前端交互修正设计

## 依据与范围

需求来自[用户清单](../redesign-agent-channel-manager/前端问题修改.md)，模块边界继承[前端架构设计](../design-frontend-architecture/design.md)。这是新的行为变更；不修改既有设计。页面协调跨模块流程，模块控制器拥有业务状态，展示组件以 props/emits 传递高级模式与草稿操作。

## 根因与方案

1. 总览不再渲染或请求插件诊断和高级组件面板，仅保留系统健康、指标与最近运行。插件页用现有诊断投影，在所属能力卡片展示状态和错误，无法归属的加载错误仍显式显示。
2. 工作流移除重复阶段导航；基本信息与运行策略卡片标题栏右侧并列控制工作流启用和高级模式，启用开关位于高级模式左侧。AIModelSelect 只有一个规范化的模型引用入口，供应商与模型字段在一次操作中原子更新，避免派生选项和旧字段形成第二来源。通知绑定复用资源中心的已保存渠道，创建/编辑渠道调用同一资源编辑器，工作流只保存资源引用和明确的覆盖。
3. Cron 使用成熟解析库 croniter，严格五段表达式，`cron: string | null` 与 `cron_timezone` 显式保存。默认 UTC 与现有后端 UTC 时间一致，前端显示时区。旧 `interval_seconds` 明确保留互斥兼容，切换 Cron 时由用户确认更改，不猜测等价表达式。调度分别使用单调时间（旧间隔）和带时区墙上时间（Cron），按下次未来到期更新，避免阻塞结束后补发历史任务。
4. 数据源抽屉头部展示保存作用域、启用与操作按钮；表单仍只有一个提交和校验入口。未选择插件时不展示无来源的参数/处理规则；选了但插件缺失则明确报错。高级配置用可折叠区域。供应商渠道的连接测试复用真实 check-connection 接口，放在模型参数操作旁，不伪造成功。
5. 运行页高级模式位于本次运行标题栏，状态由父组件传递；通知回执归过程详情。可点击 Session ID 使用链接色、hover 和键盘焦点。Markdown 继承主题背景与文字，正文对比度至少 4.5:1，代码与引用使用同一主题令牌。
6. Agent 去除重复设置、新会话和分支树入口。AI 回答分支使用 turn_id/checkpoint，用户消息编辑分支使用 message_id；两者不混淆。复制按钮位于消息外部动作栏。等待响应使用轻量状态文字，已展示内容保持稳定。模型切换只更新会话状态，不清空事件或重新装载整页。
7. 话题名通过后端管理接口和会话事件持久化，恢复时由事件重建，不能仅存在浏览器。思考展示仅消费供应商实际返回的 reasoning 内容，不推测或生成隐藏思考；正文与 reasoning 分开存入原日志，不制造第二套日志。默认折叠，用户偏好保存在浏览器展示设置中。
8. 控件过渡默认 150ms，最长 300ms；去除连续装饰骨架和没有必要的动画。请求耗时与真实后端/网络错误分别观察，不把等待时间归因于动画。流式 Markdown 避免历史内容重复解析与不必要的自动滚动。

## 验证

定向测试覆盖模型原子选择、默认模型续接、Cron 边界/时区/兼容、话题恢复、分支目标和 reasoning 事件；随后类型、架构及构建检查。真实浏览器验证交给 GPT 6 Luna max，使用现有真实后端测试装配和正式前端，记录桌面/移动、浅色/深色、控制台/网络及视觉证据。错误和未具备外部凭据的测试明确记录，不以 mock 成功替代。

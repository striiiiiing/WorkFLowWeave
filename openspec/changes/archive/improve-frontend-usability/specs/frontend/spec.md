## ADDED Requirements

### Requirement: 阅读运行报告
系统 SHALL 默认展示可读的最终报告、逐渠道通知状态和可展开的过程结果，原始 JSON 仅在高级模式展示。

#### Scenario: 正常结果与原始数据
- **WHEN** 用户打开已完成运行
- **THEN** 页面按当次存档展示结果正文、状态和时间，用户无需阅读 JSON
- **AND** 打开高级模式后可以查看和复制原始数据

#### Scenario: 正文不可用
- **WHEN** 正文未保存、过期、缺失、损坏或写入失败
- **THEN** 页面明确说明原因，不以当前配置或其他运行结果填补

#### Scenario: 运行版本更新
- **WHEN** 页面刷新到更新的运行版本
- **THEN** 全部阶段查询使用该版本，旧版本正文不混入新报告

### Requirement: 保留停用绑定
系统 SHALL 保留工作流中已绑定的停用资源及其覆盖参数，并标注停用；停用期间不得调用，再启用后仍能调用。

#### Scenario: 停用后重新启用
- **WHEN** 用户停用来源或通知渠道后运行，再将其启用并运行
- **THEN** 停用的那次不会调用该资源，启用的那次使用原有绑定和参数

### Requirement: 表单正确表达用户选择
系统 SHALL 禁止重复任务编号，切换插件时清理旧参数，正确解释 schema 引用；编号在普通模式可编辑。

#### Scenario: 编号由使用者决定
- **WHEN** 用户创建有前缀的插件资源并自行修改自动编号
- **THEN** 系统允许去除前缀且不增加额外格式限制

#### Scenario: 切换能力
- **WHEN** 用户从一个采集器或渠道切换到另一个
- **THEN** 新表单不携带旧插件字段或旧模板

### Requirement: 准确表达恢复条件与分项故障
系统 SHALL 使用后端共用恢复检查表达恢复资格，并在总览中独立展示各查询结果与失败。

#### Scenario: 恢复材料缺失
- **WHEN** 失败运行的配置或阶段存档无法恢复
- **THEN** 页面说明不能恢复的原因，不提供无效恢复入口

#### Scenario: 总览某一查询失败
- **WHEN** 插件、运行或配置查询中的一个失败
- **THEN** 其他已成功查询的数据仍展示，失败项支持重试

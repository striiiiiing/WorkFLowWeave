## Why

前端已经具备工作流、资源配置、运行报告和 Agent 会话，但代码主要按技术类型平铺。功能增长后，页面和业务组件同时承担请求、草稿、跨模块协调、事件处理和展示，难以独立迁移与回归。

用户要求先设计前端重构架构，后续在另一个 branch 实施。本变更交付有代码依据的架构草案及迁移计划，不执行前端重构。

## What Changes

- 设计 `app → pages → modules → shared` 的依赖边界，以业务模块组织代码。
- 明确服务端查询、编辑草稿、Agent 事件投影、路由和界面偏好的所有权。
- 设计 HTTP、Web 渠道 SSE、Schema 表单和错误处理的共同边界。
- 给出旧文件迁移映射、独立分支实施顺序、验证和回退要求。
- 记录现有设计与后续任务之间的差异，保留原 proposal/design 和历史任务。

## Capabilities

### New Capabilities

无。本变更只交付设计文档，`.openspec.yaml` 声明 `skip_specs: true`；这不代表后续实施可以跳过行为验收。

### Modified Capabilities

无。本次不修改产品行为或 API。后续实施若需要改变既有行为，须在实施 change 中明确对应能力增量，不能以架构迁移名义夹带。

## Impact

本次仅新增本目录的文档。预期实施影响 `frontend/src/`、前端测试、构建边界检查和前端 README；后端接口变更、数据库迁移和视觉重设计均不包含在本方案内。

详细设计见 [design.md](design.md)，本次工作和验证见 [tasks.md](tasks.md)。文档状态为待评审草案，不代表用户已批准全部技术决策或已完成代码迁移。

# 服务生命周期

依据：[模块设计](../../modules/lifecycle/design.md)、[总设计](../../design.md)。
本文件记录该活动变更的行为增量，不声明实现已经验收。

## Purpose

协调服务启动、运行准入、定时触发、显式重载与有序关闭，为调用方提供可信的本地健康状态，避免必要依赖不可用时接收新运行，并保证活动任务在释放依赖前收束。

## ADDED Requirements

### Requirement: 就绪后准入

系统 SHALL 在必要存储、配置和引用检查完成后开放新运行；启动不请求模型、采集外部来源或发送探测通知。

#### Scenario: 必要存储不可用

- **WHEN** 服务启动时无法打开必要运行存储
- **THEN** 服务报告未就绪并拒绝新运行

### Requirement: 重载和关闭边界

系统 SHALL 在插件重载时暂停新准入，有活动运行则拒绝重载；关闭先停止新触发，再等待或取消活动运行，最后有界释放依赖。

#### Scenario: 活动运行期间重载

- **WHEN** 用户请求插件重载且存在活动运行
- **THEN** 重载明确报告冲突，不取消活动运行或修改其快照

### Requirement: 健康查询无外部副作用

系统 SHALL 仅汇总已知本地状态与诊断来回答健康查询，不触发付费模型调用、外部采集或探测邮件。

#### Scenario: 读取健康状态

- **WHEN** 客户端查询健康接口
- **THEN** 返回本地就绪及诊断状态，不产生远端调用

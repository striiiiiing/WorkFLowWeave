# 通知投递

依据：[模块设计](../../modules/channel/design.md)、[总设计](../../design.md)。
本文件记录该活动变更的行为增量，不声明实现已经验收。

## Purpose

为工作流确定的输出提供可复用目标实例及单条通知投递能力，保留每次投递的真实回执和失败原因，支持邮件与文件目标，同时避免目标修改影响已经固定的运行。

## ADDED Requirements

### Requirement: 绑定原目标

系统 SHALL 按运行快照绑定通知目标，复用有效的长期实例；后续实例配置修改不得改变原运行的投递地址。

#### Scenario: 目标被修改

- **WHEN** 运行已受理后用户修改同一通知实例的地址
- **THEN** 原运行仍投递到原快照目标，新运行使用新配置

### Requirement: 真实投递回执

系统 SHALL 按每条通知的实际投递结果记录回执；邮件须取得服务端明确受理，文件通知须确认本次写入完成，失败不得报告成功。

#### Scenario: 目标拒收或不可写

- **WHEN** 邮件被拒收或文件目标本次写入失败
- **THEN** 该通知产生明确的失败诊断，已完成的分析结果仍保留

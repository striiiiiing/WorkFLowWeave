# 设计

## 提示词配置

新 Workflow 定义共享 `system_prompt`（默认空字符串）和 `input_prompt`（默认 `{input}`）。分析项与 fan-in 各有可空 `system_prompt`、可空 `input_prompt` 和 `user_prompt`。`null` 代表继承 Workflow 共享值；显式空字符串代表覆盖为空。新建分析项与 fan-in 默认继承共享值，故系统提示词默认同步，改动共享值后所有未覆盖项立即使用新值，包括 fan-in。

保留 AIConfig 的 `system_prompt` 供独立模型测试和旧资源迁移；新 Workflow 请求的系统提示词由 Workflow 层决定，不同时从 AIConfig 读取第二套默认。旧 `AnalysisTask.prompt` / `FanInConfig.prompt` 在资源加载时迁移为各项的 `input_prompt` 覆盖值：含 `{input}` 的模板直接复制，不含时改写为 `旧模板 + "\n\n{input}"`，保持本仓库旧 AI 请求中“模板在前、输入在后”的顺序。旧 AIConfig 系统提示词复制为相应项的显式覆盖值。迁移后的 API 不接收旧 `prompt` 字段。此迁移应与统一调度变更的资源版本迁移按版本顺序串接，保留一次原子发布边界。

## 请求消息

每次 AI 调用按顺序构造：

1. `SystemMessage`：本项有效系统提示词，不展开占位符。
2. `HumanMessage`：有效输入模板中 `{input}` 的字面替换结果；模板与输入各只处理一次，为未来将 `{input}` 换成多模态内容块保留独立消息位置。
3. `HumanMessage`：本项非空差异 `user_prompt`，按字面发送，不展开其中的 `{input}`。

新配置的输入模板没有 `{input}` 时沿用远端兼容规则：完整输入在前，模板正文在后；不丢失采集结果。共享模板和单项覆盖均允许用户输入不含占位符的内容。差异消息为空时不发送空消息。

fan-in 默认按 `$input`、分析项声明顺序组装输入，显式 `order` 可改序或省略 `$input`。已成功的分析结果按声明 ID 读取，完成先后不改变内容；失败项按现有 `mark_incomplete` 策略标记。fan-in 默认复用第一分析项的 AI 与模型进行一次独立汇总调用，也可选择其他项或关闭复用；复用只影响模型，不覆盖 fan-in 的系统和用户提示词。旧无 AI fan-in 迁移为关闭复用，保持原拼接行为。

## 前端与验证

编辑器显示共享系统与输入模板；在高级模式中，各分析项和 fan-in 均可对系统提示词及第二层输入模板选择“使用共享值 / 单独设置”，并编辑各自第三层差异指令。覆盖值不限制用户内容，显式空字符串也有效。fan-in 顺序与复用来源可编辑，重命名或删除分析项时同步维护引用。验证真实请求的消息顺序、字面占位符、单项覆盖、fan-in 输入顺序、模型复用、旧资源迁移、配置快照和前端保存重开。

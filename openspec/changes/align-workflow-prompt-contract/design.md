# 设计

## 单一提示词入口

Workflow 保存非空 `input_prompt`（默认 `{input}`）与可为空的 `system_prompt`。分析与汇总分别使用可空覆盖：`null` 继承对应 Workflow 字段，空系统字符串明确覆盖为空；有效输入模板不能空白。发送模型请求时，差异 `user_prompt` 必须由用户填写且不能空白，不继承分析任务差异。显式关闭模型的纯文本拼接不发送 PromptList，因此不需要差异指令。

`resolve_prompts` 独立解析前两层。只有第二层做一次 `{input}` 字面替换；未包含占位符时将完整输入放在模板前。系统和差异中的 `{input}` 保留字面值。Workflow 请求不再从 AIConfig 读取第二套系统默认。

## 消息与汇总

分析与常规模型汇总都是 `[System, Human(input), Human(差异)]`。汇总 `order` 为空时默认加入 `$input`，再按分析声明顺序拼接上一阶段结果；用户可在前端显式编辑 `order`，覆盖这一默认顺序。模型默认复用首个任务，也可独立选择或关闭模型汇总。

仅普通汇总满足一个分析任务、同供应商配置与同模型、`single_task_optimization=true` 时，发送 `[原 Task System, 原 Task 输入 Human, 原 Task 差异 Human, AI(Task 回复), Human(汇总差异)]`，仍实际调用汇总模型。此时复现的是原分析 PromptList；汇总独立前两层仅常规路径使用。高级模式提示用户这一行为，关闭优化即使用汇总自己的前两层。

Agent 汇总忽略优化配置，永远使用自己解析出的三层消息；前端不显示优化按钮。普通与 Agent 汇总共用相同的 `order` 默认与显式覆盖规则。Agent 保留运行规则，Task 系统要求合入同一条系统消息。适配器提交真实差异作为首轮用户消息，不追加固定执行指令；后续用户对话与首轮冻结结果保持独立。

## 迁移与持久化

历史独立分支的资源版本从 1 升到 2；当前主线已串接调度、Prompt、采集资源迁移，格式版本为 4，Prompt 迁移仍只在资源加载/重载边界执行，当前 API 拒绝旧 `prompt`。旧 AI 系统值成为对应 Task 显式覆盖；旧 prompt 中的指令去掉 `{input}` 后成为差异，新第二层为 `{input}`。用户手工补齐的差异及覆盖字段保持原值。无法提取非空指令的任务明确报 `prompt_migration_required`，必须由用户补齐；校验通过前不发布或覆盖原文件，不编造通用指令。旧纯拼接汇总保持 `reuse_from=null`，既有配置关闭优化以保留原行为；新建配置默认开启。

旧执行快照保持原输入模板及原请求含义，只在服务内部的历史解码边界允许没有第三层差异；此上下文不暴露给 API。旧 Agent 创建事件同样显式解码原系统值和模板；历史恢复显式复用旧固定首轮请求文本，保留请求摘要和去重身份，避免重复执行已经完成的首轮。切换 Agent 模式不生成或清空用户填写的差异。新 Agent 三段 Prompt 写入创建事件，并在重启、fork、模型变更后保留。

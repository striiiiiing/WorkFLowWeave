# 首条私聊消息连接与内置插件分离

## 用户要求（2026-10-09）

- QQ、飞书、Telegram 单向通知开启时，前端要求用户在开启期间给机器人发送第一条私聊消息，并及时反馈连接结果。
- 从首条入站事件获取目标地址，无需用户手填 chat_id / user_openid；首次回复固定为「成功连接」。
- 单向连接临时复用双向接收实现；连接完成后单向实例停止接收，后续通知只使用发送接口。
- QQ 单向发送使用 HTTP API，双向接收使用 WebSocket；Telegram 接收使用 long polling。
- 飞书原要求 webhook / long polling，经官方协议核对和用户确认「保持单聊，我搞错了」，改为应用机器人 HTTP API 发送、官方 WebSocket 长连接接收。
- 默认随应用配送的插件与用户导入的插件分离；修改系统配置与发现机制，Docker 能独立配送或挂载两类插件。

## 范围

新增统一首次连接状态、临时接收生命周期、目标地址持久化和前端反馈；保留插件协议与唯一 ChannelManager。将配送渠道移到内部插件目录，用户 plugin_dir 只存放用户导入插件及可写插件设置。邮件不参与首条消息连接。

## 验收

覆盖首次消息、精确确认文字、失败/超时/取消、重复消息、单向收尾和双向继续接收；覆盖两类目录发现、同名冲突、设置及 Docker 路径。真实平台没有收到用户首条消息时，必须报告等待或超时，不能宣称成功连接。

## ADDED Requirements

### Requirement: 文件正文复用 Workflow 输入处理

Workflow SHALL 从文件来源本次实际读取的原始正文生成独立输入视图，复用现有严格 JSON 识别、Workflow 级格式、字段/单项/总输入限额与错误策略。系统 SHALL 不把文件引用对象、路径或文件元数据当作业务正文，不用 CLI/MCP 结果伪装文件结果，不因类型是文本而跳过既有严格 JSON 判断。文件正文未构成完整严格 JSON 时 SHALL 保持原文，仅应用适用的文本限额。

#### Scenario: JSON 文本文件

- **WHEN** 文本文件内容是完整严格 JSON，Workflow 配置格式与字段限额
- **THEN** 文件正文进入与现有文本来源相同的 JSON 处理流程，原始结果保持不变

#### Scenario: 普通文本文件

- **WHEN** 文件包含普通文本、Markdown 或日志中的 JSON 片段
- **THEN** 正文保持原文并应用单项和总输入限额，不根据扩展名或局部片段强制解析 JSON

### Requirement: 新采集与历史获取结果分离

每个新运行、显式重跑采集阶段和直接采集调用 SHALL 在实际执行文件来源时重新读盘。已经完成获取的同次运行在继续分析或重试输入处理时 SHALL 使用该次获取结果；历史报告 SHALL 保留当时保存的正文，不因当前文件变化而改写。运行存档 SHALL 不作为未来实际采集的内容缓存；存档不可用时 SHALL 遵循既有明确不可恢复与显式重跑语义，不以当前文件伪造历史获取结果。

#### Scenario: 修改后启动新运行

- **WHEN** 运行 A 读取文件后，用户修改文件并启动运行 B
- **THEN** B 读取新内容，A 的已保存获取结果与报告仍保留旧内容

#### Scenario: 同次运行仅重试输入处理

- **WHEN** 本次文件获取成功但格式转换失败，用户仅重试输入处理
- **THEN** 处理复用本次原始获取结果，不重新读取可能已变化的文件

#### Scenario: 显式重跑采集

- **WHEN** 用户修改文件后明确从采集阶段重跑
- **THEN** 系统记录新的采集执行并读取新正文，不覆盖原运行的历史事实

# Workflow 输入格式选择说明

这些选项决定 **JSON 采集结果传给 Workflow AI 时** 的文本表示，整个 Workflow 使用同一选择，采集项不能覆盖。默认是“不转换”。先获取原始结果，再识别 JSON、处理字段限额、序列化，最后应用单项和总输入预算。非 JSON 文本保留原有表示，仅受适用预算约束。继续对话的 Agent 通过 MCP 代理取得新的原始结果，使用自己的输出与上下文预算，不继承这里的转换和限额。

这里的 JSON 指 MCP 的结构化业务内容，或完整可解析为一个 JSON 值的文本，不是 MCP 协议信封，也不包括日志中夹杂的 JSON 片段。图片和其他非文本内容保留在原始结果中；本次 Workflow 文本转换链不能处理时明确报错。

| 格式 | 适合的数据与阅读方式 | 选择时要知道 |
| --- | --- | --- |
| 不转换 (`none`) | 希望保留 JSON，或暂时不选择专用格式；也是默认选项。 | 没有触发限额时保留已有 JSON 原文；只有结构化值时生成 JSON 文本。已配置的限额仍生效，截取后保持合法 JSON 并标识不完整。 |
| ISON | 面向结构化记录和表格，字段名可作为表头集中出现；适合重复字段较多的结果。 | 它有自己的对象、表格和引用表示。嵌套或不规则 JSON 是否有优势，取决于实际数据。 |
| TOON | 为给模型阅读的结构化数据设计，重复对象数组可用紧凑的表头和逐行记录表示。 | 同构记录通常比较直观；实际 token 用量仍取决于数据和模型 tokenizer。 |
| ZON | 面向模型上下文的紧凑 JSON 表示，提供表格和其他编码形式。 | 语法比 Markdown/CSV 专门化；不应把项目宣传的压缩比例当作每次运行的保证。 |
| Markdown (`md`) | 希望 AI 同时阅读层级和数据表时。 | 可读性优先；转换器须正确表达层级、转义及值类型，不自行生成分析标题或总结。复杂内容未必节省 token。 |
| CSV (`csv`) | 字段固定、记录扁平的表格。 | 转换器须明确支持的表格形状和空值、字符串、数字的表达规则。嵌套和混合结构不自动展开；无法保持字段和值含义时报告不支持。 |

格式化不自行过滤或汇总字段，也不承诺某种格式始终最省 token。预算不足时，结构化内容按原顺序保留可表达的片段并重新序列化；截取标识放在业务正文之外，且自身也占用预算。不会把半个 JSON、断开的 CSV 引号或过期的 TOON 数组长度当作有效输出。预算连最小有效片段和必要标识都容纳不了时明确报错。

字段限额针对 JSON 叶子值：字符串保留前缀，数字、布尔值和 null 不切成另一个值；容器与子值不重复计量。单项及总预算还覆盖字段名、结构语法、来源说明与分隔符。未来的按字段过滤属于独立处理步骤，本次不提供字段选择或删除规则。

TOON 等格式携带的数组长度属于格式语法；系统仍不额外生成业务记录统计。所选转换器若不能表达数据，应返回明确错误，不暗中换用“不转换”或其他格式。具体计量、继承与多模型约束见 [Workflow 契约](specs/workflow/spec.md)。

## Python 实现参考

- [ISON 官方项目](https://github.com/ISON-format/ison) 提供 [Python 包 `ison-py`](https://pypi.org/project/ison-py/)，包含 ISON 的解析和序列化能力。
- [TOON 官方 Python 实现](https://github.com/toon-format/toon-python) 提供 `toon_format.encode/decode`，仓库注明 beta 并给出 GitHub 源码安装方式。2026-09-28 核对时，仓库关于 PyPI beta 的说明与 [PyPI 的 `toon-format`](https://pypi.org/project/toon-format/) 元数据不一致：后者为 `0.1.0` 且仍自称占位包。实施时须锁定并验证实际分发来源和版本，不能仅凭包名认定转换已可用。
- [ZON 官方项目](https://github.com/ZON-Format/ZON) 提供 [Python 包 `zon-format`](https://pypi.org/project/zon-format/)；不要与 PyPI 上用途不同的 `zon` 包混淆。

以上是格式来源与选型提示，不预设各库能无损转换所有 JSON 形状；实施时须用本项目支持的输入样例验证。Markdown 与 CSV 不要求专门的第三方格式库。

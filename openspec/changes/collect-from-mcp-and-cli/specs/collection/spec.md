## ADDED Requirements

### Requirement: MCP 与 CLI 并列采集来源

系统 SHALL 允许采集项选择 MCP 服务、原始工具名及调用参数，或选择 CLI 指令。一个采集项 SHALL 只具有一种来源类型。来源配置 SHALL 描述一次确定的调用及采集项限额覆盖，不承担工具实现、业务统计或格式转换。Workflow SHALL 在本次运行的配置快照下执行调用，不让 AI 临时搜索或替换已配置的工具。MCP 调用 SHALL 使用 [共享 MCP 能力](../mcp-runtime/spec.md)。

#### Scenario: 固定 MCP 工具采集

- **WHEN** 用户为采集项选择 MCP 服务、工具和参数并运行 Workflow
- **THEN** Workflow 直接请求该工具，按其 schema 校验参数；工具不可用或参数不合法时报告错误，不搜索另一个工具替代

#### Scenario: 相同工具具有不同采集参数

- **WHEN** 两个采集项引用同一 MCP 工具但配置不同参数或限额
- **THEN** 系统保留两个采集项的身份、调用和处理结果，MCP 服务定义只引用同一份配置

### Requirement: 来源参数配置视图

前端 SHALL 保持选择来源、填写参数、保存采集项的流程。MCP 表单 SHALL 根据共享目录中的工具 schema 展示参数，不维护另一份手写参数定义；目录未加载、加载失败和工具确实不存在 SHALL 可区分。CLI SHALL 明确区分可执行程序及 argv 与显式 shell 指令，保存所选执行方式和工作目录；系统 SHALL 不通过猜测空格或管道符悄悄切换执行方式。

#### Scenario: MCP 工具参数变化

- **WHEN** 刷新目录后，已保存工具的 schema 与表单原先使用的版本不同
- **THEN** 表单显示当前定义并报告不再满足定义的参数，保留用户原配置以便修正，不静默删除参数或补造值

#### Scenario: 用户配置 shell 指令

- **WHEN** 用户明确选择 shell 指令并配置管道或重定向
- **THEN** 系统使用该执行方式运行指令；argv 模式中的同样字符保持普通参数，不自动解释为 shell 语法

### Requirement: 获取原始结果与输入处理分离

采集阶段 SHALL 保留来源身份、实际调用状态和原始结果。MCP SHALL 保留原始结果信封中的内容块、结构化内容和错误标记；CLI SHALL 分别保留 stdout、stderr 和退出状态。CLI 的 stdout SHALL 作为待处理正文，stderr SHALL 作为诊断内容，不自动混入正文。JSON 识别、字段限额、格式转换及输入预算 SHALL 由 [Workflow 输入处理](../workflow/spec.md) 产生独立视图，不改写原始结果。

#### Scenario: CLI 同时输出正文和诊断

- **WHEN** 指令成功退出，stdout 是 JSON，stderr 包含日志
- **THEN** 原始结果保留两路输出，Workflow 只从 stdout 识别 JSON，不因混入日志而破坏正文

#### Scenario: 转换失败

- **WHEN** 来源已成功返回，但所选格式不能表达其 JSON
- **THEN** 保留获取成功事实和原始内容，另行报告该项输入处理失败，不把它改写成来源调用失败或空结果

### Requirement: 采集事实不依赖业务计数

系统 SHALL 区分成功、无内容、来源缺失、失败和超时，不要求来源返回记录数，不自动统计业务条数。MCP 的工具错误标记、协议错误和 CLI 非零退出 SHALL 保持失败事实，即使附带可读内容也不能当作成功采集正文。合法 JSON 的 `0`、`false`、`null`、`[]` 和 `{}` SHALL 保留为实际内容，不通过真假值或业务条数判断为空；只有没有正文内容时才报告无内容，已返回内容但下游不支持其类型属于输入处理错误。来源自带的业务计数字段 SHALL 作为普通数据保留。

#### Scenario: 有内容但没有记录数

- **WHEN** MCP 或 CLI 成功返回可消费内容而没有记录数字段
- **THEN** 采集成功，系统不补算条数，也不要求返回旧 Collector 的正计数

#### Scenario: 工具以内容块报告失败

- **WHEN** MCP 返回 `isError: true` 并附带文本，或 CLI 输出部分正文后以非零状态退出
- **THEN** 系统记录失败及原始诊断，不把附带内容当作成功输入，也不伪装为空结果

### Requirement: 恢复不隐式重做来源调用

系统 SHALL 分别记录来源获取与输入处理的结果。原始结果可用时，输入处理重试 SHALL 复用该结果，不重新调用 MCP 或 CLI。恢复无法取得原始结果时 SHALL 明确报告不可恢复，由既有显式重跑语义决定是否重新采集；不能为了重新生成视图隐式重做外部操作。对已发出但结果未知的调用 SHALL 保留不确定事实，不能宣称未执行或自动当作安全重试。

#### Scenario: 仅重新处理已保存结果

- **WHEN** 转换阶段失败，且存档策略保留了原始结果，用户重试该处理阶段
- **THEN** 系统复用原始结果进行处理，不再次执行来源调用

#### Scenario: 原始内容未存档

- **WHEN** 进程重启后恢复运行，而所需原始内容按存档策略未保存
- **THEN** 系统报告内容不可用，不通过重新调用外部来源伪装为原运行恢复

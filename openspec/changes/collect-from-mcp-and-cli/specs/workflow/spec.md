## ADDED Requirements

### Requirement: 从原始结果提取可处理内容

Workflow SHALL 在获取完成后，从独立的原始结果生成输入视图。MCP 的 `structuredContent` SHALL 作为结构化数据处理；`content` 中的文本块及 CLI stdout SHALL 仅在整个文本构成一个严格 JSON 值时识别为 JSON，否则保持原文。系统 SHALL 不从日志、Markdown 代码围栏或多段文本中猜测提取 JSON，不把 MCP 协议信封当作业务数据转换。JSON 标量、对象和数组 SHALL 均可被识别，重复键及非标准 JSON 数值不得通过宽松解析静默丢失信息。

存在 `structuredContent` 时 SHALL 先呈现其视图，再按原顺序处理其他内容块；与其 JSON 类型和值完全一致的 JSON 文本副本 SHALL 不重复加入 AI 输入，其他说明文字 SHALL 保留。若选择 `none` 且未触发限额，存在等价文本副本时 SHALL 使用首个副本作为该结构化内容的原文表示。非文本内容 SHALL 保留在原始结果中；当前文本输入处理无法表达的内容 SHALL 报告明确的不支持错误，不将图片、二进制或资源引用悄悄当作空正文或 JSON。

#### Scenario: 普通文本恰好含有 JSON 片段

- **WHEN** CLI stdout 是日志加 JSON，或 MCP 文本块包含 JSON 代码围栏
- **THEN** 整段作为非 JSON 文本保留，只应用单项和总输入限额，不猜测移除外围文本

#### Scenario: 结构化内容附带说明

- **WHEN** MCP 返回结构化 JSON、相同 JSON 的文本副本以及另一段说明文字
- **THEN** JSON 只处理一次，说明文字仍按非 JSON 内容保留；该项的共同限额约束两者组成的输入

### Requirement: Workflow 级 JSON 输出格式

系统 SHALL 允许用户在 Workflow 级选择 `none`、`ison`、`toon`、`zon`、`md` 或 `csv`。选择 SHALL 固定在运行快照中，采集项和来源覆盖 SHALL 不能覆盖它；未配置时 SHALL 使用 `none`。前端 SHALL 显示名称、适用场景和限制，依据 [格式说明](../../formats.md) 帮助选择。非 JSON 文本 SHALL 不因该选择发生格式转换。

选择 `none` 且未触发限额时，原始 JSON 文本 SHALL 保留原有表示；只有结构化值而无原文时 SHALL 使用确定的 JSON 序列化。触发限额后 SHALL 仍用 JSON 表达保留内容。格式转换 SHALL 只改变表示，不自行过滤、汇总字段或改写值的含义。转换器 SHALL 声明支持的数据形状及值映射；无法保留其支持范围内字段和值的语义时 SHALL 报告处理错误，不静默换格式、展开嵌套字段或生成摘要。

#### Scenario: 不同来源共享格式

- **WHEN** 同一 Workflow 的两个采集项返回 JSON，第三项返回普通文本
- **THEN** 两个 JSON 项使用本次快照中的同一格式，第三项保持文本表示；来源配置不能单独选择格式

#### Scenario: 不转换且没有截取

- **WHEN** 用户选择 `none`，来源返回带缩进的 JSON 文本且未触发限额
- **THEN** 该正文的缩进与文本表示保留，不重新压缩或排版

#### Scenario: 格式不支持输入形状

- **WHEN** 用户选择 CSV，但 JSON 超出转换器声明支持的表格形状
- **THEN** 该项报告格式不支持，保留原始结果，不静默展开字段或回退 JSON

### Requirement: 分层限额配置与继承

系统 SHALL 支持 Workflow 级总输入、单项和 JSON 字段 token 限额。配置值 SHALL 为正整数或未设置；Workflow 省略或使用 `null` 表示该级不限额，采集项省略或使用 `null` 表示继承 Workflow 值。采集项 SHALL 只能用明确的正整数覆盖单项和字段限额，不能覆盖格式或总输入限额。限额的最终有效值 SHALL 在运行开始时解析并进入快照，运行途中修改配置不改变当前输入处理。

#### Scenario: 采集项覆盖局部限额

- **WHEN** 一项覆盖字段和单项限额，其他项继承 Workflow
- **THEN** 各项使用解析后的局部限额，所有项共同受同一总输入限额约束；局部限额较大也不能突破总限额

#### Scenario: 未设置限额

- **WHEN** Workflow 未设置任何限额，采集项也没有正整数覆盖
- **THEN** 本处理链不主动截取内容，不填入未经配置的 token 上限；模型自身上下文容量仍独立存在

### Requirement: 字段处理、格式化与预算顺序

系统 SHALL 按“识别内容 → JSON 字段限额 → 所选格式序列化 → 单项预算 → 按配置顺序汇合并应用总预算”生成输入视图。字段限额 SHALL 递归作用于 JSON 叶子值，包括数组中的标量和根标量，以值的 JSON 标量表示计量；对象和数组容器不与子值重复计量。字符串 SHALL 保留满足限额的前缀；数值、布尔和 null SHALL 保持原子值，不能截成另一个值或改变类型，无法容纳最小有效表示时报告字段预算不足。字段名与容器结构开销 SHALL 计入后续单项和总预算。

非 JSON 文本 SHALL 只受单项和总预算约束，按原文顺序保留前缀。JSON 在单项或总预算下需要进一步缩减时 SHALL 按原顺序保留结构片段并重新序列化，必要时缩短字符串或省略尾部成员，不直接截断序列化字符串造成无效 JSON、TOON、ISON、ZON、表格行或 CSV 引号。限额处理 SHALL 不修改原始结果，也不冒充未来的按字段筛选能力。

#### Scenario: 不转换但限额生效

- **WHEN** `none` 模式下 JSON 超出字段或单项限额
- **THEN** 输出仍是合法 JSON，保留未受影响值的类型与含义；如有内容截取则在正文外标识不完整，单纯去除表示中的空白不冒充数据缺失

#### Scenario: 非 JSON 超限

- **WHEN** 普通文本超过单项限额
- **THEN** 保留原文前缀并标识截取，不解析字段、不重新排版，也不使用所选 JSON 转换格式

#### Scenario: 并发采集的总预算分配

- **WHEN** 后配置的采集项先完成，且所有内容不能同时进入总预算
- **THEN** 仍按配置顺序保留先前项和边界项的可容纳片段，不因完成顺序改变保留内容，并明确标识被省略的来源

### Requirement: token 口径与不完整标识

系统 SHALL 使用实际消费共享采集输入的模型所对应的 token 计量能力执行限额，包括直接消费该输入的汇总模型；多个模型口径不同时，生成的同一输入 SHALL 同时满足各模型口径下的已配置限额。所需计量能力不可用时 SHALL 明确报错，不能用字符数估算却宣称满足硬 token 限额；未启用限额时不要求为此计量。

单项预算 SHALL 包含该项的来源标识、格式说明和截取标识；总预算 SHALL 包含整个共享采集输入的分隔符、来源及省略说明。它 SHALL 不被描述为整次模型请求的预算，系统提示、其他消息和输出空间由模型调用层另行管理。截取标识 SHALL 与业务数据分开，既出现在输入视图元数据中，也告知分析模型；不能往用户 JSON 中注入可能重名的内部字段。预算连最小有效表示及必要标识都容纳不了时 SHALL 明确报告预算不足，不超限发送或制造来源为空的结论。

#### Scenario: 标识也占用预算

- **WHEN** 某项正文已占满预算，需要额外注明截取
- **THEN** 系统为标识重新分配预算或报告预算不足，不在超额正文外继续追加标识

#### Scenario: 多模型 token 口径不同

- **WHEN** 两个分析模型对同一输入计得的 token 数不同
- **THEN** 输入按两个口径均满足限额后再共享，不能仅按其中一个模型校验

### Requirement: 输入处理状态与业务计数分离

Workflow SHALL 分别暴露获取状态、输入处理错误和预算截取事实；获取成功而转换失败 SHALL 进入明确的处理失败路径，并按来源错误策略决定停止或继续其他来源，不能静默传入原文。截取不等同于来源失败或无内容。分析项 SHALL 收到按配置顺序汇合的有效输入、必要来源身份及不完整说明，系统 SHALL 不补算业务条数或附加旧采集计数。用户需要统计时 SHALL 可交由 Workflow AI；来源本身的计数字段、格式必要的数组长度语法和执行限额所需的 token 计量不属于自动业务统计。

#### Scenario: 转换失败但其他来源可用

- **WHEN** 一个来源转换失败，其他来源处理成功，且失败来源策略允许继续
- **THEN** Workflow 保留失败原因并使用其他有效输入，不把失败项的原始内容混入所选格式

#### Scenario: 多来源无业务计数

- **WHEN** 多个来源处理成功但未提供业务计数
- **THEN** 分析项收到正文及来源信息，不收到系统补算的条数

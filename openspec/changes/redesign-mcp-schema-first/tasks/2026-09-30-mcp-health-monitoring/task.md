# MCP 健康探测与自动监控

## 任务与依据

本任务基于现有 MCP SDK runtime、`MCPServerConfig` 资源仓库和资源配置中心实现；不修改既有 proposal/design。运行时设计已要求目录探测优先使用 `server/discover`、不支持时回退 `tools/list`，因此单次健康探测复用 `MCPRuntime.load(..., refresh=True)`，避免增加第二套连接协议。

- [x] 为 MCP 资源增加自动探测开关，默认关闭；增加分钟间隔，默认 30 分钟，仅校验为正整数，不设置人为上限。
- [x] 增加后端单次探测 API，返回健康状态、检查时间、连接耗时、工具数量和脱敏错误。
- [x] 增加按资源间隔运行的生命周期后台调度；资源更新时重建计划，关闭时停止调度。
- [x] 在资源配置中心增加单次“探测健康”操作、结果展示和自动探测配置。
- [x] 删除前后端业务代码中对外部产品名称的专有词汇，保留 `servers`/`mcpServers` 输入兼容语义。
- [ ] 运行完整后端/前端回归、构建和真实 MCP HTTP 烟测。

## 默认值与取舍

- 自动探测默认关闭：用户明确要求默认不主动连接远端服务；只有显式开启后才建立周期任务。
- 默认间隔 30 分钟：按用户要求；单位直接落在资源字段 `health_check_interval_minutes`，输入只要求 `>= 1`，不使用小的前端 `max` 或后端 `le` 限制。
- 单次探测强制刷新工具目录：现有 runtime 已把 `server/discover`/`tools/list` 和 transport 超时封装在 `load`，复用它能确保“健康”代表真实协议连接，而不是只检查缓存。
- 探测失败返回结构化的 `unhealthy` 报告而非伪造成功；服务不存在、越权等配置边界错误继续通过统一错误处理返回。

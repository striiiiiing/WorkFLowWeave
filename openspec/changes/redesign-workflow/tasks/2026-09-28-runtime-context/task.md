# 构图与运行解耦

## 授权和依据

用户批准继续原生编译图 stream_channels 输出方案，并明确要求修改六个构图参数的设计，让构图与一次运行解耦。本任务依据 design §1.1、§3、§5、§6；本次获得 design 修改授权，不修改 proposal。此前最小真实链路任务保留其当时证据，不覆盖成新方案已经通过。

## 不变量与实施

- [ ] build_workflow 仅接收 checkpointer；执行器生命周期只编译一次，恢复查询也复用该图。
- [ ] 单项任务使用原生 Send 和 per-invocation 子图；配置与业务项数量不进入构图闭包。
- [ ] 能力、采集调用上下文和原配置的内存视图经 Runtime Context 注入；配置权威仍为父图 checkpoint。
- [ ] semaphore 和 fresh intent 集合每次执行新建，跨 session 不共享；恢复不继承发送许可。
- [ ] 原生事件的 input/output 带业务身份，sessionID 仍由统一入口注入；不制造新的业务 taskID。
- [ ] Luna max 验证 Context→Send→子图传播、输出边界、子图发现、不同配置并发执行与真实中断恢复。
- [ ] 迁移故障注入到真实持久化边界，完成相关回归、静态检查、构建和最终差异审查。

## 默认值与边界

复用设计已有并发与保留默认值，不新增调度器、构图缓存或运行超时。原生 v2 事件队列无界按用户要求仅记录、不解决。外部 snapshot/页面生命周期协议继续待讨论，不因内部上下文重构改变。

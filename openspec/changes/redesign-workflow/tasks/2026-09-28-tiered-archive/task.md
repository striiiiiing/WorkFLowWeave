# 分类归档、提示词索引与独立保留期

日期：2026-09-28。本轮只修改设计契约；运行代码未实施，不运行应用测试。

依据：[design 第 3.2、5.1–5.4 节](../../design.md)、[流式执行规范](../../specs/workflow-stream-execution/spec.md)、[checkpoint 规范](../../specs/workflow-checkpoint-resume/spec.md)。旧日期任务保留历史，本次补充取代统一保留期及父图入口无限期保留的假设。

## 用户要求与决定

| 决定 | 依据与理由 |
| --- | --- |
| 采集、分析、最终报告三类独立正文 | 用户明确要求拆成三份；同一 SessionStore 管理分类记录及共用索引，不新增三个数据库/服务 |
| 不可变提示词版本去重 | 用户指出系统提示词大多相同；按内容和格式版本去重，归档配置/结果关联原版本，不查询当前配置解释旧结果 |
| 执行 state 仍保存内容 | 延续用户已确认的 checkpoint 执行权威方案；归档索引不成为执行时读取正文的外部引用 |
| 四类保留期独立配置 | 用户纠正“长于采集、短于报告”的硬性文字；通常 checkpoint、采集、分析、报告依次留得更久，只是建议，不能添加顺序校验、联动调整或配置拒绝 |
| 分析与最终报告默认不过期 | 用户明确指定；checkpoint/采集的具体默认数值未给出，文档不臆造天数，留作实施前配置决定 |
| checkpoint 到期后停止接收对应 resume | checkpoint 本身有保留期，长期正文可读不代表执行入口仍有效；不新增从归档重建图的恢复模式 |
| 过期不级联删除其他类别 | 每类独立保留；留下来源身份和 expired 标记，报告不因采集删除而丢失，共用提示词有保留的追溯引用时仍保留 |
| 归档按原期限处理 | 使用同轮共同时间基准，重放或迟到归档不重置已有期限；活动执行及未归档唯一副本遵循原有交接保护 |

共用提示词仅保存模板/静态内容，避免把动态采集输入或完整请求藏进长期共享记录；遵循 snapshot 备份开关。已有归档迁移保留固定版本和截止时间，不因去重重新延长保留或复活过期内容。

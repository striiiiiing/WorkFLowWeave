# Workflow 精简与实时业务进度修订任务

## 状态与依据

依据用户本轮确认、[proposal](../../proposal.md)、[design 第 4、5.6 节](../../design.md) 和 [流式规范](../../specs/workflow-stream-execution/spec.md)：核心目标为精简 Workflow 和前端实时业务进度；正文采用 checkpoint 引用方案。推送选择 fan-out 单项成功、fan-in 完成、逐渠道发送成功，不以整个子图或全部内部节点为粒度。此前任务记录保留，本轮只修改文档。

## 设计任务

- [x] 1.1 将两个核心目标及工作逻辑/消费子模块的职责写入 proposal 和 design。
- [x] 1.2 明确必要推送点、tags 分类与稳定业务身份、错误状态和异步推送时序。
- [x] 1.3 明确 SessionStore 查询投影与必要业务提交的区别，正文引用及备份、清理、固定版本的既定方案。
- [x] 1.4 执行 OpenSpec 严格校验、链接及差异检查，记录结果。

## 实施与验证任务

- [x] 2.1 分离工作逻辑与消费子模块，复用现有生命周期、存储及查询，不额外建立通用事件总线或执行器。
- [x] 2.2 在必要业务节点/可运行对象配置分类 tags；核验当前版本公开 stream 格式中的逐任务更新、namespace、tags/metadata，形成明确分类映射，过滤继承 tags 的内部事件。
- [ ] 2.3 接入 interaction 订阅和前端消费，按 session/轮次/事件类别/item 或 output/channel 定位条目，处理必要失败和不确定投递状态。
- [x] 2.4 通过可控慢分支验证 fan-out 成功项在兄弟分支及 arrange 结束前已显示；验证 fan-in 完成一次更新、单渠道回执提交后推送而不等待其他渠道。
- [x] 2.5 验证初始化、路由、intent、纯排序不触发业务完成推送；fan-in 关闭不伪造模型汇总事件；父子重复更新不重复条目或版本。
- [x] 2.6 验证断开不取消后台运行、重连查询补齐、慢消费者有界背压及关闭，不新增无界后台任务。
- [x] 2.7 检查 checkpoint/pending writes 不复制正文、关闭备份不落盘、子图清理不破坏业务版本、旧正文过期不回退到新正文。
- [ ] 2.8 后端定向测试每个命令硬超时 60 秒，再执行适用静态检查、前端构建与真实订阅烟测；未经生产验证不得勾选。

## 决策依据与默认值

| 决策 | 依据与理由 |
| --- | --- |
| 两个目标及选择性推送 | 用户明确提出精简和实时体验，随后限定三类推送点；不能扩大为每个节点完成都广播 |
| 旧草图的核对范围 | 已按用户指示读取仓库外 LogAgent-design-notes/redesign-workflow-2026-09-28/workflow.py.txt 及 subgraph/collectors.py.txt，确认 subgraphs=True、按 tags 消费必要过程信息的意图；具体三类粒度以用户本轮澄清为准，不恢复 ToolNode、逐 chunk 建线程、fork 或草图保留时长 |
| 两部分职责 | 用户前轮要求工作逻辑与 astream 消费子模块；LangGraph 唯一调度，消费者负责观察、投影和推送 |
| 正文采用引用 | 用户比较改动范围后接受；现有 workflow/session_store.py 保存正文与业务版本，protocols.py 的 SessionReader 要求固定版本读取 |
| 必要提交在执行路径 | workflow/nodes.py 的 archive_node 在发布引用前等待保存；通知 intent 必须先于发送，确定 receipt 必须先于成功推送 |
| tags 不作唯一身份 | 并行分支可共享 tags，内部调用可能继承；以业务身份定位，避免串项与重复投影 |
| 无新延迟默认 | 用户允许协程等待；以快分支先于慢分支完成被显示验收，不虚构毫秒 SLA、轮询间隔或发送批次默认 |
| 重连复用查询 | astream 不等于持久化消息日志，现有查询提供已提交事实，无需新增消息历史存储 |
| 其他默认保持 | 沿用 design 第 7 节并发、备份与保留默认，无新增预算或保留期依据 |

# 模型多选与 MCP 目录失败诊断

依据：[现有设计](../../design.md) 的草稿发现、显式添加、过期响应隔离，以及用户本轮追加的“发现 35 个模型但没有下拉列表，应该多选”。不修改 proposal/design；多选是本轮明确要求，候选仍不自动写入渠道。MCP 依据 [共享目录设计](../../../redesign-mcp-schema-first/design.md) 的失败状态区分。

## 根因与范围

- `AIModelList.vue` 的自动补全在点击时立即以旧候选调用回调，HTTP 返回后的候选变化不会刷新已打开的建议列表；仅显示发现数量无法完成选择。这是异步状态与控件契约的结构性修复，用响应式多选选项替代一次性建议回调，不叠加刷新补丁。
- 实际后端 MCP 状态为 `FileNotFoundError`，后端环境中找不到 `qqmusic-mcp`。导入配置不会安装命令。运行时补充命令/工作目录/PATH 诊断，采集源复用统一错误格式化，避免 `String(ApiError)` 丢掉诊断详情。
- 模型列表的非 JSON 响应未经边界转换，最终变成通用 JSONDecodeError；在响应解析处保留状态码和正文，明确提示检查 API 路径。不猜测或自动重写供应商 URL。

## 实施与验收

- [x] 多选下拉在请求完成后直接更新，支持搜索、手工输入、批量显式添加，保留原模型参数；新模型参数仍为 `{}`，依据现有配置契约使用供应商默认值。
- [x] 加载状态来自现有发现请求；不增加请求缓存、额外超时或第二套候选存储；配置变化与过期请求仍由原 composable 管理。
- [x] 补充 MCP 缺失命令诊断并在采集源显示，错误保持失败状态。
- [x] 非 JSON 模型列表报告可操作原因，沿用现有凭据脱敏及不重试规则。
- [ ] 定向单测、静态检查、构建、无头浏览器验证、最终 diff 审查。

用户明确要求仅使用独立无头浏览器。Playwright 使用现有临时后端与本地 HTTP 供应商夹具，验证 35 个模型延迟到达后显示、多选两个并持久化；不操作用户真实浏览器和实际资源。

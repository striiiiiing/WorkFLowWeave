# 剩余前端问题修复设计

## 边界与依据

问题和暂缓项见 [原清单](../redesign-agent-channel-manager/前端问题修改.md)。既有 `POST /ai/{id}/check-connection` 只读取已保存资源，因此新建或修改连接时无法按当前输入发现模型。`AIService.list_models` 已负责配置校验、凭据解析、超时和上游错误归类，新的 HTTP 入口直接复用它。

## 后端

- 新增 `POST /ai/discover-models`，请求体为当前 `AIConfig`，响应为上游模型 ID 列表；不保存资源，不改写 `models`，返回 `Cache-Control: no-store`。
- 前端的临时明文密钥先使用既有 `/credentials/protect` 转成加密凭据引用，再把引用放入发现请求；后端继续由统一凭据解析器解密。环境变量引用沿用现有配置规则。发现失败返回真实错误，不构造成功列表。
- 清理已取消的“测试模型”HTTP 入口及专用请求类型。模型发现只做 `/v1/models` 查询，不发送聊天请求。

## 前端

- 模型名称输入框每次点击触发一次异步发现。请求以当前服务地址、凭据方式和超时设置组成草稿；新建渠道无需先保存。发现结果只作为候选，不自动添加模型。连接配置变化后旧候选清空，较晚完成的旧请求不能覆盖新配置。地址或密钥缺失时显示明确提示。
- 工作流列表每张卡片的“从最新结果继续”放在操作行左侧。加载最新可续接运行及模型目录后，若浏览器默认模型仍可用，直接创建并进入 Agent；未设置或已失效时展示选择对话框。运行详情已有同样语义，列表入口与它保持一致。
- Agent 思考过程只渲染服务端实际发送的 `reasoning` 数据，默认折叠；全局设置可改变默认展开状态。验收包括事件流与持久化回放，供应商没有发送思考数据时不显示空容器。

## 取舍和默认值

不增加模型发现缓存或防抖：用户明确要求每次点击请求，且连接凭据和地址可能刚被修改。前端仅在组件当前生命周期内屏蔽过期响应；HTTP 超时沿用 `AIConfig.timeout`，不另立第二套预算。默认模型仅在当前 `/agents/models` 目录中存在时自动使用，避免用过期本地引用创建失败会话。思考过程默认折叠，依据原清单的明确要求。
